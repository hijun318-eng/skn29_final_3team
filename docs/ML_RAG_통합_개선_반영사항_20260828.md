# ML·RAG 통합 개선 반영사항

- 작성일: 2026-08-28
- 대상 로컬 브랜치: `codex/jaehong-rag-ml-completion`
- 반영 대상 원격 브랜치: `origin/jaehong`
- 비교 기준: `jaehong` 계열 구현과 `daesung` 브랜치의 보안·운영 경계

## 결론

ML 예측 결과는 별도 화면, 패널, 모달, 사이드바를 만들지 않고 기존 분석 대화의 에이전트 응답 카드로만 표시한다. RAG는 기능 확장보다 승인 문서, 역할 권한, 유효기간, 인용 근거가 모든 조회 경로에서 동일하게 적용되는 것을 우선한다.

## 이번 반영 내용

### ML

1. 별도 `MLPredictionWorkspace` 레이아웃과 전용 입력 폼을 제거했다.
2. 기존 분석 대화 입력에서 `[객실 예측]`으로 명시된 요청만 ML 경로로 실행한다.
3. 자동 키워드 분류로 예측을 선택하지 않는다. 사용자가 선택한 명시적 경로만 사용한다.
4. ML runtime의 capability에서 호텔, 예측 가능 기준일, 최대 예측 기간을 확인한다.
5. 지원하지 않는 호텔이나 누락된 호텔은 같은 대화 카드에서 보완 선택지를 제공한다.
6. 예측값, 기준일, 모델 버전, Trino query provenance를 기존 에이전트 메시지 안의 카드로 표시한다.
7. ML 기능은 `ML_FEATURE_ENABLED=1`로 명시 승인된 환경에서만 활성화한다.

### RAG

1. 대화 명령의 RAG 진입을 `requested_route=INTERNAL_GUIDELINE`인 경우로 제한했다.
2. 일반 분석 질문을 키워드만으로 내부지침 검색에 자동 전환하지 않는다.
3. 벡터 검색과 article hydration에 `approval_status=APPROVED` 조건을 추가했다.
4. 문서 목록과 PDF 원문에도 검색과 같은 역할, 승인, 유효성, 시행일, 만료일 필터를 적용했다.
5. 문서 목록과 PDF 조회 시 검증된 Gateway 역할을 RAG 서비스까지 전달한다.
6. 답변 API 키 또는 endpoint가 없으면 더미 설정으로 실행하지 않고 즉시 실패한다.
7. 생성된 답변 본문이 비었을 때 검색 원문을 답변처럼 대신 노출하지 않고 오류로 처리한다.
8. 비교 답변은 검증된 문서 수 제한을 일관되게 적용한다.
9. RAG는 `RAG_FEATURE_ENABLED=1`, Gateway HMAC secret, answer transport가 명시된 환경에서만 활성화한다.

## 기존 개선 중 유지한 내용

- 비교 질문과 후속 질문에서 최대 두 문서의 검증된 문맥을 보존하는 로직
- 사용자가 특정 조항을 후속 질문으로 요청했을 때 해당 조항을 선택하는 보정
- 근거에 정확한 승인 담당자가 없을 때 담당자를 만들어내지 않는 응답 처리
- 검색 evidence ID와 answer citation ID의 일치 검증

## 운영 적용 전 필수 확인

1. `ML_FEATURE_ENABLED=1`, `RAG_FEATURE_ENABLED=1`은 각 기능의 승인 완료 후 운영 환경에서만 설정한다.
2. `RAG_GATEWAY_HMAC_SECRET`, `RAG_ANSWER_API_KEY`, `RAG_ANSWER_ENDPOINT`를 Secret 저장소에서 주입한다.
3. ML model hash, feature cutoff, Trino query ID가 예측 응답에 포함되는지 확인한다.
4. 역할별 승인 문서 목록과 PDF 직접 조회가 같은 결과 범위를 갖는지 확인한다.
5. 최신 RAG E2E 평가를 다시 실행해 semantic completeness의 수동 검토 항목을 승인 또는 반려한다.

## 후속 개선 후보

이번 변경과 별도로 다음 항목은 추가 검증 후 반영해야 한다.

1. ML 결과를 서버 대화 턴으로 영속화해 새로고침 후에도 동일한 카드가 복원되도록 한다.
2. RAG 로컬 답변기의 `EvidenceSafetyGate` 재결합은 최근 승인 담당자·조항 선택 보정과 충돌하지 않도록 회귀 테스트를 먼저 추가한다.
3. 도메인별 문서 제목 prefix와 비상 대응 fallback 문구를 제거하고 검색 품질 평가 데이터로 대체한다.
4. 최신 커밋 기준 ML/RAG E2E 증적 보고서를 다시 생성한다.

## 수용 기준

- ML 별도 레이아웃이 렌더링되지 않는다.
- ML 결과는 기존 `.message--agent` 내부에서만 표시된다.
- 명시하지 않은 일반 질문은 ML 또는 RAG로 자동 전환되지 않는다.
- 미승인, 역할 범위 밖, 시행 전, 만료 문서는 검색·목록·PDF 어느 경로에서도 반환되지 않는다.
- 빈 생성 답변을 검색 원문으로 대체하지 않는다.
- feature flag와 필수 secret이 없는 환경은 안전하게 실패한다.
