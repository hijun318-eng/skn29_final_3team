운영

통합 기준 정리

작업 기록, DataHub 정리, 가벼운 AI 모델 전환과 단계별 통합 기준을 정리했습니다.

이번 주 작업은 네 가지 축으로 정리할 수 있습니다. 먼저 분석 화면은 요약과 주요 지표를 우선 제공하고, 추가 요청에 따라 표와 그래프를 보여주도록 개선했습니다. 보고서는 AI가 바로 수정하지 않고 사용자가 승인한 내용만 반영하도록 만들었습니다. 관리자, 문서 검색, 수요예측과 보고서 기능은 실제 시스템에 연결했습니다. 마지막으로 작업 기록과 DataHub 관리 기준, 가벼운 AI 모델 전환과 단계별 통합 방법을 정리했습니다.

DataHub·분석

자동 용어 생성을 중단하고 1,258건을 정리했으며, 기간 비교·조건 검증·오류 추적을 강화했습니다.

가장 큰 성과는 분석 결과와 보고서 수정 과정에 사용자 확인 단계를 만든 것입니다. 화면에서는 요약과 주요 지표를 먼저 보여주고, 추가 요청에 따라 표와 그래프를 제공합니다. 보고서 편집 기능은 문서 방향, 금액 단위, 표와 그래프, 배치와 페이지 수정안을 제안하고, 사용자가 승인한 뒤 반영합니다. 실패하면 기존 문서와 변경 기록을 보존합니다. 이와 함께 관리자 계정, 작업 기록, 문서 검색, 7일 객실 수요예측, DataHub 용어 정리와 오류 추적도 진행했습니다.

03 · 남은 문제

기능은 연결됐지만,전체 시스템 확인이 남았습니다

04 / 06
3

통합 전 반드시 닫아야 할
검증 경계

R1

문서 검색 정확도 — 질문과 맞지 않는 답변을 줄이고, 실제로 찾은 자료 안에서만 답하도록 보완해야 합니다.

R2

실제 분석 연결 — 인증 설정을 정리한 뒤 DataHub·Trino·데이터베이스를 같은 버전과 계정 권한으로 확인해야 합니다.

R3

Neo4j 범위 — 8월 26일 선택형 그래프 이식 후 되돌린 이력이 있어, 핵심 경로와 분리한 상태로 재검토합니다.

남은 문제는 세 가지입니다. 첫째, 일부 질문에서 맞지 않는 답변이 나와 문서 검색 정확도를 높여야 합니다. 둘째, 인증 설정을 해결하고 DataHub, Trino, 데이터베이스와 AI 모델을 같은 버전과 같은 계정 권한으로 연결해 실제 분석을 확인해야 합니다. 셋째, Neo4j 기능은 한 번 적용했다가 다시 제외한 기록이 있습니다. 따라서 현재 완료된 기능으로 보지 않고, 꼭 필요한 기능인지와 어떤 방식으로 연결할지를 다시 검토하겠습니다.

[Sources] 사용자 제공 2026-08-25·26 일일보고; 선택 기능 적용·되돌림 이력; 저장소 AGENTS.md의 same-release live 검증 규칙.

핵심 원칙: 각 단계는 변경 내용 정리 → 규칙 확인 → 다시 테스트 후 다음 단계로 이동기존 동작을 비교 기준으로 활용

통합은 첨부 계획대로 여섯 단계로 진행합니다. 먼저 분석 요청 처리 규칙을 확정하고 변경 내용을 정리합니다. 다음은 기존 이력을 보존하면서 문서 검색과 수요예측 기능을 연결합니다. 여러 AI 기능은 내부 코드를 직접 섞지 않고 연결 지점에서 결합합니다. 보고서 기능은 관련 파일만 선별해 충돌 범위를 줄입니다. 화면은 현재 디자인을 기준으로 최종 서버 기능과 연결합니다. 마지막으로 배포 후보를 만들고 전체 테스트, 데이터베이스 변경, 브라우저와 실제 외부 시스템 연결을 확인합니다. 기존 동작은 통합 결과를 비교하는 기준으로 사용하겠습니다.
