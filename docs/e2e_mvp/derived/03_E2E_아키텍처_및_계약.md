# E2E 아키텍처 및 계약

## 1. 런타임 구조

```text
React Frontend
  → Backend API / Authentication / request_id
  → Node 1 Interpreter
  → DataHub Metadata + Asset Binding + Business Rule + Permission
  → Context Builder / G1
  → Node 2 SQL Generator
  → G2 SQL Policy / 최대 1회 Repair
  → Trino / Source read-only account
  → G3 Result Validation / Shaping / Masking
  → Node 3 Narrator
  → App PostgreSQL Analysis Artifact / Run / Trace
  → Frontend Table / Chart / Evidence / Report Draft
```

Orchestrator는 단계·분기·timeout·retry와 최종 상태를 결정한다. AI 모델은 권한, SQL 실행 허용과 Gate 합격을 결정하지 않는다.

## 2. 역할과 책임

| 평가 관점 | 현재 구성 | 책임 | 금지 |
|---|---|---|---|
| Planner | Controller + Router + Node 1 | 상태 전이, 질문 구조화, 확인 필요 판단 | 자유 반복, 권한 결정 |
| Metadata | DataHub + Binding + Rule + Context + G1 | 승인 자산·Metric·기간·JOIN·권한 Context | 임의 Metric·JOIN 생성 |
| Query | Node 2 + Repair + Trino adapter | 승인 Context 기반 SQL 초안, 1회 수정, 실행 | 직접 승인, 쓰기 실행 |
| Validation | G1·G2·G3 + SQLGlot + Trino | Context·SQL·Result의 결정론적 판정 | LLM의 자체 합격 판정 |
| Report | Node 3 + Artifact + Report domain | Safe Result 설명, 저장·재실행 | 결과 재계산, 과거 결과 덮어쓰기 |

## 3. Slice 1 API 계약

### 요청

```http
POST /analysis
Authorization: Bearer <session token>
Content-Type: application/json
```

```json
{
  "question": "2026년 5월과 6월 GOLD 고객의 객실·식음 통합 매출을 보여줘.",
  "parameters": {}
}
```

- Slice 1의 신규 질문은 기간을 자연어에 포함하고 Frontend가 별도 기간 파라미터를 보내지 않는다.
- 저장된 Analysis 재실행은 성공 응답에서 확정한 `period_start`, `period_end_exclusive`를 파라미터로 사용할 수 있다.
- `period_end_exclusive`는 미포함 경계다.

### Node 1 출력

필수 구조:

```json
{
  "metric_candidates": ["approved_metric_id"],
  "selected_metric_id": "approved_metric_id",
  "period_candidates": [
    {
      "start": "2026-05-01T00:00:00+09:00",
      "end_exclusive": "2026-07-01T00:00:00+09:00",
      "source_text": "2026년 5월과 6월"
    }
  ]
}
```

- Metric과 Dimension 값은 승인된 business term ID만 허용한다.
- 기간 후보는 정확히 하나여야 Context에 반영한다.
- Node 1이 물리 자산, JOIN, 권한과 SQL을 결정하지 않는다.

### 확인 필요 응답

```json
{
  "data": {
    "status": "BLOCKED",
    "result": null
  },
  "error": {
    "code": "CONTEXT_INCOMPLETE",
    "message": "질문이 여러 지표로 해석될 수 있습니다. 분석할 기준을 선택해 주세요.",
    "retryable": false,
    "suggestions": ["인식 객실 매출", "숙박일 배분 객실 매출"]
  }
}
```

- `suggestions`는 사용자에게 허용된 승인 Metric의 고유한 업무명만 포함한다.
- 내부 예외, Metric ID, 원시 FQN과 권한 밖 후보는 노출하지 않는다.
- 이 응답 뒤에는 Node 2·G2·Trino·G3·Artifact 성공 단계가 없어야 한다.

### 성공 Evidence

성공 응답은 최소한 다음을 연결한다.

- 확정 기간 `start`, `end_exclusive`
- 사용 Source의 DataHub URN과 Trino FQN
- `query_id`, `artifact_id`, `request_id`, `trace_id`
- `context_release`, `policy_version`, `model_version`
- sampling과 masking 적용 여부
- G1·G2·G3 trace와 `repair_count`

## 4. Context와 Gate 계약

### Context Builder

```text
Structured Question
+ Role-filtered DataHub Assets
+ Active Asset Bindings
+ Metric / JOIN / Time / Identity Rules
= Approved Context Package
```

- 기간 후보 0개 또는 2개 이상은 `PERIOD_REQUIRED` 내부 상태로 차단한다.
- 승인 Metric을 하나로 확정할 수 없으면 `INVALID_METRIC` 내부 상태와 안전한 제안을 만든다.
- 외부 API에서는 둘 다 `CONTEXT_INCOMPLETE`로 정규화하되 메시지와 제안으로 사용자 행동을 구분한다.

### G1

- Metric·Dataset·Binding·JOIN·기간·권한·활성 Version을 검사한다.
- 실패하면 Node 2를 호출하지 않는다.

### G2

- 단일 `SELECT` 또는 `WITH ... SELECT`만 허용한다.
- Approved Context 밖 자산·컬럼·JOIN·함수와 DDL/DML/CALL/passthrough를 차단한다.
- 정형 오류만 Node 2 Repair에 전달하고 수정은 최대 1회다.

### Trino

- G2 통과 SQL만 실행한다.
- Source DB read-only 계정, timeout, cancellation, result cap과 Query ID를 적용한다.

### G3

- Result Schema·크기·민감정보·JOIN 증폭 신호와 Evidence를 검사한다.
- 통과 전 Raw Result를 Frontend나 Node 3에 전달하지 않는다.

## 5. 상태와 오류 계약

| 단계 | 상태 | 대표 오류 코드 | 실행 상한 |
|---|---|---|---|
| 인증 | HTTP `401`/`403` | `ACCESS_DENIED` | 분석 미시작 |
| Context/G1 | `BLOCKED` | `CONTEXT_INCOMPLETE`, `ACCESS_DENIED` | Node 2 0회 |
| Node 2/G2 | `BLOCKED` 또는 `FAILED` | `SQL_POLICY_BLOCKED` | Repair 최대 1회 |
| Query | `FAILED` 또는 `PARTIAL` | `QUERY_SOURCE_FAILED`, `PARTIAL_FAILURE` | bounded timeout/retry |
| G3 | `BLOCKED` 또는 `FAILED` | `RESULT_EVIDENCE_MISSING`, `INSUFFICIENT_EVIDENCE` | 외부 결과 0건 |
| 완료 | `SUCCEEDED` 또는 `PARTIAL` | 없음 또는 `PARTIAL_FAILURE` | Artifact 저장 |

오류 응답은 사용자 메시지와 내부 trace reference를 분리한다. stack trace, Secret, 민감 SQL literal과 private chain-of-thought는 반환하거나 저장하지 않는다.

## 6. 모델 Provider 계약

- Node 1·2·Repair·3은 역할별 prompt와 strict output schema를 사용한다.
- 실제 provider와 model은 환경 설정과 실행 시 Release Manifest로 확정한다.
- 현재 실행 기준은 `21_AI_작업_인수인계_현재진행상황.md`를 따른다.
- Node 2의 provider adapter 경계는 유지하지만 RunPod 또는 특정 sLLM을 P0 완료 조건으로 고정하지 않는다.
- 외부 model endpoint 장애는 template·fixture 결과로 대체하지 않고 명시적으로 실패한다.

환경 변수 이름은 현재 코드의 provider adapter 계약을 따른다.

```text
MODEL_MODE
OPENAI_ENDPOINT
OPENAI_API_KEY
OPENAI_MODEL
NODE2_MODEL_ENDPOINT
NODE2_MODEL_API_TOKEN
NODE2_MODEL
MODEL_TIMEOUT_SECONDS
```

`NODE2_MODEL_*`은 별도 Node 2 provider를 사용할 때만 활성화한다. Secret은 `.env`에만 두고 코드·로그·문서·Git에 기록하지 않는다.

## 7. Slice 1 변경 경계

| 영역 | 예상 변경 |
|---|---|
| `src/ai/node1.py` | 한국어 단일 월·연속 월을 하나의 반개방 기간으로 정규화 |
| Backend contracts/response | `ErrorBody.suggestions`와 OpenAPI 반영 |
| Context/pipeline | 기간 후보 개수 검증, 승인 Metric 제안, fail-closed |
| Frontend analysis client | 질문만으로 분석 요청 가능 |
| Agent/상태 UI | 별도 날짜 입력 제거, 승인 Metric 선택과 재질의 |
| Tests | Node 1, Context, API/OpenAPI, Frontend contract 회귀 |

Report editor, 새 Source, 새 Metric, model training과 배포는 Slice 1 변경 경계가 아니다.

## 8. Slice 1 검증 계약

최소 자동 검증:

```text
Node 1 기간 정규화 단위 테스트
Context 기간·Metric 모호성 테스트
Analysis 오류 응답·OpenAPI contract 테스트
Frontend 요청·제안 선택 contract 테스트
기존 1 Source·3 Source 관련 회귀
```

제품 Exit Gate:

```text
공식 Compose 기동
→ 질문만 포함한 실제 HTTP 정상 요청
→ Metric 확인 필요 실제 HTTP 요청
→ 기간 누락 차단 요청
→ 브라우저 제안 선택·재질의
→ Evidence·Query·Artifact·저장 기간 대조
```

단위·계약 테스트만 통과한 상태는 Slice 완료가 아니다.
