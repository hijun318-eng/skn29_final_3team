# E2E 아키텍처 및 계약

## 구조

```text
React Frontend
  -> Backend API / Auth
  -> Node 1 Interpreter
  -> DataHub Core / G1 Context
  -> Node 2 SQL Generator
  -> G2 SQL Policy
  -> Trino
  -> G3 Result Contract
  -> Node 3 Narrator
  -> App PostgreSQL Artifact
  -> Frontend Table / Chart / Report Draft
```

## 컴포넌트 책임

- Frontend: 입력, 진행 상태, 서버 결과 표시만 담당한다.
- Backend: 인증, node routing, Context 결합, 정책 검사, 실행과 저장을 조정한다.
- DataHub Core: 허용 asset·metric·column·join·filter를 확정한다.
- Node 1: 자연어를 구조화하며 권한과 dataset을 결정하지 않는다.
- Node 2: 승인된 Context 안에서 SQL 초안을 만들며 직접 실행하지 않는다.
- Trino: 검증된 read-only SQL만 실행한다.
- Node 3: 실제 Result를 설명하며 수치나 근거를 새로 만들지 않는다.

## 모델 계약

- Node 1과 Node 3는 OpenAI-compatible endpoint를 사용한다.
- Node 2는 별도 RunPod vLLM endpoint와 `answervice-sql` adapter를 사용한다.
- 모든 node 출력은 strict JSON Schema를 만족해야 한다.
- Node 2는 `sql`, `used_assets`, `used_metrics`를 반환한다.
- SQL은 단일 `SELECT` 또는 `WITH ... SELECT`, 최대 `LIMIT 1000`, 결정적인 정렬을 사용한다.

Secret은 `infrastructure/database/.env`에만 두며 코드·로그·문서·Git에 기록하지 않는다.

## 안전 경계

- G1: 권한과 Context 허용 범위
- G2: SQL read-only·asset·metric·filter·기간·LIMIT 검사
- G3: Result schema, row 제한, provenance와 Artifact 일치
