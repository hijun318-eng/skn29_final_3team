ANSWERVICE 분석 결과·Artifact·보고서 HTML/PDF 과거 파생 자료
문서 상태: ARCHIVED — REFERENCE ONLY

이 문서는 다음 두 가지를 함께 제공한다.

1. 사용자가 제시한 방향을 실제 구현 가능한 제품 요구사항으로 구체화한 명세
2. 이 명세를 코드와 실제 브라우저 화면으로 달성하기 위한 실행용 목표 프롬프트

용어 표기
- [확정]: 사용자가 명시한 제품 방향
- [제안]: 구현 안정성과 사용자 경험을 위해 이 문서에서 구체화한 기본안
- [후속 확정]: 구현 전에 제품·계약 담당자와 결정해야 하는 항목

===============================================================================
0. 결론
===============================================================================

[확정] ANSWERVICE의 분석과 보고서 관계를 다음과 같이 바꾼다.

자연어 질문
  -> 분석 실행
  -> 분석 결과 1개
  -> Artifact 1개
  -> 여러 Artifact를 하나의 HTML 보고서 초안에 조합
  -> 사용자가 검토·편집·확정
  -> 확정 시 PDF 버전 생성

핵심 관계는 다음과 같다.

- 분석 결과 1개 : Artifact 1개
- Artifact 1개 : 관련 KPI·복수 차트·표·요약·근거를 묶은 분석 결과 패키지
- 보고서 1개 : Artifact N개 + 사용자가 작성한 제목·본문·주석·권장 액션 블록
- HTML 보고서 : 편집 가능한 초안 및 검토본
- PDF 보고서 : 확정된 특정 HTML 버전의 서비스 내 수정 불가 스냅샷

[결정] “분석 결과”가 Artifact를 거치지 않고 보고서에 직접 연결되는 이중 경로는 만들지 않는다. 화면에서는 사용자가 “분석 결과”를 고르는 것처럼 보여도, 보고서에 삽입되는 실제 참조 단위는 해당 결과에서 생성된 Artifact여야 한다. 그래야 출처, 버전, 권한, 단위, PDF 재현성을 한 경로로 관리할 수 있다.

[결정] HTML 편집은 사용자가 임의의 raw HTML을 입력하는 기능을 뜻하지 않는다. 구조화된 보고서 문서와 Block Editor를 WYSIWYG HTML Canvas로 렌더링한다. 임의 HTML 실행은 XSS, 인쇄 불일치, 레이아웃 파손을 유발하므로 허용하지 않는다.

[결정] PDF의 “수정 불가능”은 ANSWERVICE 안에서 해당 최종본을 덮어쓰거나 다시 편집할 수 없다는 의미다. 외부 PDF 편집 도구까지 기술적으로 차단할 수 있다고 표현하지 않는다. 수정이 필요하면 최종본을 복제해 새 HTML 초안 버전을 만들고 다시 확정한다.

===============================================================================
1. 제품 객체와 책임
===============================================================================

1.1 Analysis Result

- 한 번의 분석 실행이 만든 검증된 결과다.
- 질문, 적용 기간, 호텔/조직 범위, 필터, 지표, 결과 데이터, 상태, 생성 시각을 가진다.
- Node2 응답 구조나 분석 단계 수가 확정되지 않은 동안 Frontend가 임의 필드를 사실처럼 고정하지 않는다.
- 실제 계약에 없는 요약·원인·권고·단위를 UI에서 추측해 채우지 않는다.

1.2 Artifact

- 하나의 Analysis Result를 사용자가 읽고 재사용할 수 있게 구성한 버전 고정 분석 패키지다.
- Artifact 하나에는 같은 분석 결과를 설명하는 여러 표현이 들어갈 수 있다.
  예: 핵심 KPI 4개 + 월별 추이 Line + 채널 비교 Bar + 구성비 100% Stacked + 상세 Table.
- “차트 하나 = Artifact 하나”로 쪼개지 않는다. 사용자가 요구한 1:1 관계와 여러 그래프 표현을 동시에 만족시키려면 Artifact가 복수 View를 소유해야 한다.
- Artifact 전체가 Report Editor에서 하나의 최상위 Drag & Drop 요소다.
- P0에서는 Artifact 내부 View를 별도 독립 블록으로 뜯어내는 기능을 만들지 않는다. 대신 보고서 안에서 Artifact의 표시 모드를 “요약형 / 표준형 / 상세형”으로 바꾸고, 선택 가능한 View의 표시 여부만 조절한다.
- Artifact 원본 데이터와 근거는 보고서 편집으로 변조하지 않는다. 보고서에서는 배치, 크기, 표시 모드, 보조 제목, 설명, 보이는 View만 바꿀 수 있다.

Artifact에 필요한 개념 필드:

- artifact_id, version
- analysis_result_id, analysis_run_id
- owner/tenant와 접근 권한
- 사용자 질문 원문(기본 화면에 제목으로 노출하지 않음)
- 사람이 읽는 Artifact 제목
- 기간, 호텔/조직, 필터, 데이터 기준 시각
- summary
- kpis[]
- views[]: chart/table/metric/narrative 등
- 각 View의 metric, dimension, unit, display unit, precision, comparison basis
- provenance/evidence/limitations
- status: READY/PARTIAL/STALE/ERROR/UNSUPPORTED 등 확정된 계약 상태
- created_at, source_version, checksum

위 이름은 개념 계약이며 현재 Backend 필드명으로 즉시 고정하지 않는다. 실제 OpenAPI와 저장 모델을 확인한 뒤 ADR과 Versioned Schema로 확정한다.

1.3 Report Draft

- 여러 Artifact와 작성 블록을 조합한 편집 가능한 문서다.
- 저장 원본은 구조화된 Report Document이며 HTML은 그 렌더링 결과다.
- 최소 속성은 title, orientation, page size, unit policy, blocks, revision, dirty/saved 상태, 작성자, 수정 시각이다.
- 한 Report 안에서 Artifact를 여러 개 넣을 수 있다.
- 동일 Artifact 중복 삽입은 허용하되 첫 중복 시 “같은 분석 결과가 이미 포함되어 있습니다”를 알리고 사용자가 계속할 수 있게 한다.

1.4 Report Final / PDF

- 사용자가 확정한 Report Draft revision과 사용된 Artifact version을 동결한 최종본이다.
- PDF 생성 시 보고서 제목, 방향, 금액 단위, 페이지 수, Artifact 버전, 생성자, 생성 시각, checksum을 함께 기록한다.
- 최종 PDF는 서비스에서 내용 수정·블록 이동·Artifact 교체가 불가능하다.
- “새 버전으로 편집”은 최종 PDF를 바꾸는 기능이 아니라 동일 스냅샷으로부터 새 Draft를 만드는 기능이다.
- Artifact에 최신 버전이 생겨도 기존 확정 PDF는 바뀌지 않는다.

1.5 기존 데이터 호환

- 기존 “분석 1개 -> 보고서 1개” 데이터는 Artifact 1개가 들어간 Report로 읽을 수 있어야 한다.
- 기존 Report를 열었다는 이유만으로 자동 저장하거나 배치를 재작성하지 않는다.
- Migration 전후의 Report/Artifact 권한과 소유권이 유지되어야 한다.

===============================================================================
2. 사용자에게 보이는 분석 출력 두 종류
===============================================================================

2.1 AI 답변이 포함된 분석 요약

목적: 질문 직후 빠르게 결론과 다음 행동을 이해하게 한다.

기본 구성:

1. 질문 원문을 복사하지 않은 의미 있는 분석 제목
2. 한 문단 또는 최대 3개의 핵심 요약
3. 가장 중요한 KPI 1~3개
4. 질문에 가장 적합한 대표 시각화 1개
5. 적용 기간·호텔·필터·데이터 기준 시각
6. 계산/근거를 확인하는 진입점
7. 이어서 물을 수 있는 후속 질문 또는 행동

이 화면에서 “모든 분석 과정이 완료되었습니다” 같은 시스템 중심 문구를 결론보다 앞세우지 않는다. Loading, Partial, Error 같은 상태는 필요하지만 사용자의 판단 정보와 분리한다.

2.2 상세 분석 결과 Artifact

목적: AI 요약을 검증하고 보고서에서 재사용할 수 있는 완전한 분석 결과를 제공한다.

기본 구성:

1. Artifact 제목과 상태
2. 분석 범위·기간·필터·데이터 최신 시점
3. 핵심 요약과 KPI
4. 같은 분석 결과를 설명하는 복수 시각화
5. 상세 결과 표
6. 해석된 조건·계산 기준·근거·제약
7. 보고서에 추가하는 Primary action

UI 용어는 사용자에게 “상세 분석 결과” 또는 “분석 결과”로 보이고, 내부 재사용 단위를 Artifact로 유지한다. “분석 결과 보고서”와 최종 조합 Report를 같은 이름으로 부르지 않는다.

3. 보고서 제목 정책
===============================================================================

[확정] 보고서 제목은 사용자의 자연어 질문 원문이 되면 안 된다.

[제안] 제목은 다음 정보의 조합으로 만든다.

- 기간: 2026년 7월, 2026년 2분기, 2026.05~2026.06
- 대상: 워커힐, GOLD 고객, 온라인 채널
- 주제/지표: 영업 실적, 통합 매출, 객단가, 예약 취소율
- 분석 목적: 현황, 추이, 비교, 원인 분석, 운영 보고

좋은 예:

- 2026년 7월 영업 실적 보고서
- 2026년 5~6월 GOLD 고객 통합 매출 비교 분석
- 2026년 2분기 채널별 객실 매출 및 객단가 현황

나쁜 예:

- “지난달보다 워커힐 매출이 왜 떨어졌는지 알려줘”
- “GOLD 고객 5월 6월 비교해줘”
- “분석 결과”

규칙:

- AI가 제목 후보를 만들 수 있지만 자동 확정하지 않는다.
- Draft에서는 제목을 편집할 수 있고 PDF 확정 전에 반드시 확인한다.
- 제목 후보를 만들 근거가 부족하면 “YYYY년 MM월 운영 분석 보고서”처럼 안전한 템플릿을 사용한다.
- 질문 원문은 근거 Drawer에서만 확인하고 제목 fallback으로 사용하지 않는다.
- 제목은 1줄을 기본으로 하며 긴 경우 2줄까지 허용한다. 말줄임표로 핵심 대상을 숨기지 않는다.

4. A4 HTML 보고서 형식
===============================================================================

4.1 물리 규격과 브라우저 Viewport 구분

- A4 세로: 210mm x 297mm
- A4 가로: 297mm x 210mm
- 1440x900과 1024x900은 Editor를 검증하는 브라우저 Viewport이지 보고서 크기가 아니다.
- HTML Canvas와 PDF는 px가 아니라 A4 mm 규격과 Print CSS를 기준으로 맞춘다.

[제안] 기본 Print-safe 여백:

- 세로: 좌우 14mm, 상하 14~16mm
- 가로: 좌우 12~14mm, 상하 12mm
- Footer와 페이지 번호를 위한 안전 영역을 별도로 확보한다.
- 실제 로고·폰트·차트 Label이 잘리지 않는지 PDF Render 결과로 최종 조정한다.

Editor의 Application Chrome은 현재 ANSWERVICE의 어두운 Enterprise UI를 유지할 수 있다. 다만 실제 보고서 Canvas는 첨부 레퍼런스처럼 흰색/밝은 종이 표면을 사용한다. 이는 인쇄 가독성과 PDF 재현성을 위한 역할 분리이며 브랜드 변경이 아니다. Navy·Blue를 주 강조색으로, Neutral을 구조와 본문에, Green/Red/Orange를 의미 상태에 제한한다.

4.2 A4 가로 — Executive Dashboard Report

참조: 사용자가 첨부한 두 번째 이미지.

목적:

- 회의, 경영진 브리핑, 한눈에 비교하는 운영 대시보드
- 한 페이지에서 가장 중요한 상태와 변화, 원인, 액션을 파악

기본 레이아웃:

1. Header: Answervice Logo, 보고서 제목, 기간, 작성일, Draft/Final 상태
2. KPI Row: 핵심 KPI 4개를 같은 정렬축에 배치
3. Main Visual Row: 대표 차트 3개
   - 시간 추이
   - 구성비 또는 세그먼트 비교
   - 금액/순위 비교
4. Insight + Action Row: 핵심 인사이트와 권장 액션
5. Footer: 데이터 출처, 기준 시각, 생성 근거, 검토 안내, 페이지 번호

레이아웃 규칙:

- 한 페이지 Overview를 기본으로 한다.
- 핵심은 좌상단부터 배치한다.
- 네 개 KPI와 세 개 차트를 억지로 유지하기 위해 글자와 차트를 축소하지 않는다.
- 긴 Label, 많은 Series, 상세 표가 필요하면 2페이지로 넘기거나 상세형 Artifact를 다음 페이지로 보낸다.
- 불필요한 Scroll을 PDF에 만들지 않는다.

4.3 A4 세로 — Narrative Analysis Report

참조: 사용자가 첨부한 첫 번째 이미지.

목적:

- 차트와 표뿐 아니라 해석·변화 원인·권장 액션을 순서대로 읽는 문서
- 검토, 공유, 기록, 결재에 적합한 서술 중심 보고서

기본 읽기 흐름:

1. Header: Logo, 제목, 기간, 작성일, Draft/Final 상태
2. 핵심 요약
3. 주요 KPI
4. 분석 차트와 표
5. 주요 변화 분석
6. 권장 액션
7. 데이터 출처·근거·한계·페이지 번호

레이아웃 규칙:

- 기본은 여러 페이지를 허용한다.
- KPI Label이 짧을 때는 4열, 길거나 단위가 복잡하면 2x2로 자동 재배치한다.
- 차트는 2열을 우선하되 최소 가독 폭을 만족하지 못하면 한 줄 1개로 배치한다.
- 제목과 다음 문단, 차트 제목과 차트, 표 Header와 첫 행이 페이지 경계에서 분리되지 않게 한다.
- Artifact 전체가 남은 공간보다 크면 다음 페이지로 이동한다.
- 한 Artifact가 한 페이지보다 큰 상세형일 때만 명시적 “계속” 표기와 함께 내부 Section 단위로 나눈다.

4.4 방향 변경

- 방향 선택은 Report 생성 시 명확히 제공한다.
- 편집 중 가로/세로 전환도 가능하지만 자동 재배치 Preview와 Undo를 제공한다.
- 세로를 단순히 가로 Canvas의 폭만 줄인 형태로 만들지 않는다.
- 각 방향은 같은 콘텐츠를 보존하되 서로 다른 안전한 Layout Preset을 사용한다.
- 방향 변경으로 숨겨지거나 잘리는 블록이 있으면 확정 전에 목록으로 알린다.

4.5 Print CSS와 Page Break

- @page size를 A4 portrait/landscape로 명시한다.
- Canvas, PDF Renderer, Preview가 같은 Versioned Design Token과 Render Component를 사용한다.
- KPI, Chart, Table Header, Callout에는 break-inside 정책을 둔다.
- 인쇄 시 Editor Toolbar, Drag/Resize Handle, Hover UI, Toast, Drawer가 보이지 않는다.
- 표가 여러 페이지에 걸리면 Header를 반복한다.
- 차트는 Raster Screenshot으로 대충 캡처하지 않고 Font와 Vector 품질을 유지할 수 있는 렌더 경로를 우선한다.

===============================================================================
5. HTML 초안 -> 확정 PDF 수명주기
===============================================================================

상태 흐름:

DRAFT_HTML
  -> REVIEW_READY
  -> CONFIRMING
  -> PDF_GENERATING
  -> FINAL_PDF

실패 상태:

- SAVE_FAILED
- PREFLIGHT_BLOCKED
- PDF_GENERATION_FAILED
- ARTIFACT_UNAVAILABLE
- STALE_ARTIFACT_WARNING

동작 규칙:

- DRAFT_HTML은 편집, 자동 저장, Undo/Redo가 가능하다.
- REVIEW_READY는 내용이 잠기는 상태가 아니라 Preflight가 통과한 검토 가능 상태다.
- 확정 버튼은 결과를 되돌릴 수 없음을 설명하고 현재 revision과 Artifact version을 보여준다.
- PDF 생성 중에도 사용자는 다른 화면으로 이동할 수 있고 진행·성공·실패 알림을 다시 확인할 수 있다.
- 생성 실패를 Final로 표시하지 않는다. 원인을 보여주고 같은 Snapshot으로 재시도한다.
- FINAL_PDF는 서비스 안에서 편집 불가다.
- FINAL_PDF 수정 요청은 “새 버전으로 편집”을 통해 새 DRAFT_HTML을 만든다.

확정 전 Preflight 필수 항목:

- 의미 있는 제목 존재
- 보고서 방향과 페이지 수 확인
- 모든 Artifact 접근 가능 및 version 고정 가능
- 단위 미확인 Currency View 없음
- Chart/Table Overflow, 잘림, 겹침, 빈 페이지 없음
- 데이터 기준 시각과 출처 표시
- Loading/Error Placeholder가 최종 출력에 남아 있지 않음
- Font 및 Logo Asset 로드 성공
- 금액 단위, 반올림, %와 %p 사용 일관

[제안] 최종 PDF는 사용자의 브라우저 Print 기능만으로 확정하지 않는다. 재현 가능한 Server-side Chromium 계열 Renderer 또는 동일한 Versioned Render Job을 사용하고, 외부 Network 의존 없이 Font/Asset을 포함한다. Client Print는 Preview 또는 임시 출력으로만 사용한다.

6. 금액·수치 단위 시스템
===============================================================================

6.1 사용자가 선택할 수 있는 보고서 기본 금액 단위

- 자동
- 원
- 천 원
- 만 원
- 백만 원
- 억 원

6.2 단위 우선순위

1. 신뢰 가능한 Metric/Artifact 계약의 원본 통화·단위
2. 보고서 단위 설정
3. 해당 Chart/Table의 명시적 Override

Column 이름에 revenue, price, amount가 들어간다는 이유만으로 KRW를 추측하지 않는다. 원본 단위가 확인되지 않으면 “단위 확인 필요” 상태로 표시하고 최종 PDF Preflight를 막는다.

6.3 자동 단위 규칙

- 자동 단위는 한 Report의 주요 금액 값 범위를 보고 한 번 선택한다.
- Card마다 제각각 억/만/원으로 바뀌지 않는다.
- 서로 규모가 크게 다른 View는 해당 View만 Override할 수 있지만 Chart 제목 옆에 단위를 반드시 표시한다.
- 단위 변경은 원본 값을 바꾸지 않고 표시 배율과 Format만 바꾼다.
- PDF 확정 시 선택된 단위와 반올림 규칙을 동결한다.

6.4 표시 규칙

- 숫자는 ko-KR 천 단위 구분과 tabular numerals를 사용한다.
- 단위는 KPI 값, Chart 우상단, Table Header 중 문맥에 맞는 한 곳에 명확히 둔다.
- Table Cell마다 같은 단위를 반복하지 않는다.
- Tooltip과 상세 표에서는 원 단위의 정확한 값을 확인할 수 있게 한다.
- 큰 값은 3~4자리 수준으로 읽기 쉽게 축약하되 근거 값을 숨기지 않는다.
- 음수는 Minus sign과 문구를 함께 사용하고 색만으로 전달하지 않는다.
- 0, null, 데이터 없음, 계산 불가, 오류를 서로 다른 값과 상태로 표현한다.
- 비율 변화는 %와 %p를 구분한다.
  예: 점유율 45% -> 47%는 +2%p이며 +4.4% 상대 증가일 수 있다.
- 명, 건, 실, 박, %, %p 같은 비금액 단위도 같은 Formatter 계약을 사용한다.

7. 여러 그래프 표현과 Chart System
===============================================================================

7.1 원칙

- 그래프 종류가 많다는 사실 자체를 품질로 보지 않는다.
- 하나의 분석 결과가 여러 질문에 답할 때 같은 Artifact 안에 여러 적합한 View를 제공한다.
- 사용자는 추천 View와 대안 View를 선택할 수 있지만 데이터 구조에 맞지 않는 Chart를 억지로 허용하지 않는다.
- 하나의 Artifact에 기본 1~4개의 시각화와 상세 표를 권장한다. 정보가 많으면 Report에서 여러 Artifact로 이야기 순서를 구성한다.

7.2 의도별 기본 시각화

- 단일 핵심 값: KPI Card, Big Number, Goal 대비 Bullet
- 시간 추이: Line, Area
- 범주 비교/순위: Horizontal Bar, Vertical Bar
- 여러 계열 비교: Grouped Bar, Multi-line(Series 수 제한)
- 누적 기여: Stacked Bar
- 구성비 비교: 100% Stacked Bar
- 단순 부분-전체: Donut. 범주가 적고 합계가 의미 있을 때만 사용
- 상관 관계: Scatter
- 증감 기여/브리지: Waterfall
- 값과 목표/비율의 혼합: Composed Chart. 두 축의 의미가 분명할 때만 사용
- 상세 검증: Table

P0 권장 범위:

- KPI
- Line/Area
- Horizontal/Vertical Bar
- Grouped/Stacked/100% Stacked Bar
- Donut
- Scatter
- Composed Bar+Line
- 읽기 중심 Table

P1 검토 범위:

- Waterfall
- Bullet
- Heatmap
- Histogram/Box Plot

제외 또는 별도 요구가 필요한 범위:

- 3D Chart
- 장식용 Gauge 남용
- 임의 Dual-axis 조합
- 무제한 Series Builder
- 지도/공간 분석
- Excel 수준 편집

7.3 공통 Chart Anatomy

모든 Chart는 가능한 범위에서 다음을 갖는다.

- 분석 결론을 설명하는 제목
- 기간·비교 기준을 보완하는 부제
- 단위
- 읽을 수 있는 Axis와 Tick
- 일관된 Legend 순서와 색
- Tooltip의 Label, 원값, 표시값, 비교값
- Data source와 최신 시점
- Empty/Error/Partial/Stale 상태
- Screen Reader용 요약과 동일 데이터 Table 대안

7.4 색상과 가독성

- 기존 ANSWERVICE Navy/Blue를 Primary Series와 강조에 유지한다.
- Green/Red/Orange는 좋은 변화/나쁜 변화/주의의 의미가 계약으로 확인될 때만 사용한다.
- 같은 Metric/Category는 화면과 PDF에서 같은 색 의미를 유지한다.
- Grid line은 보조선으로 약하게 사용하고 장식적 Gradient와 Shadow를 줄인다.
- 핵심 결론을 Hover Tooltip에만 숨기지 않는다.
- 긴 한글 Legend는 줄바꿈, 줄임+Tooltip, 하단/우측 재배치 중 가독성이 가장 높은 방식을 사용한다.

7.5 라이브러리 결정

현재 Recharts는 이미 Chart Library다. 기본적으로 보이는 원인은 라이브러리 부재보다 Token, Tooltip, Axis, Legend, Label, Empty/Error, 반응형 구성의 미완성일 가능성이 크다.

- 기존 Recharts의 ResponsiveContainer, Custom Tooltip/Legend, Composed Chart, accessibilityLayer를 먼저 사용한다.
- 공통 EnterpriseChart와 Chart Token을 완성한다.
- 새 라이브러리는 실제 Fixture로 재현한 요구를 Recharts가 충족하지 못한다는 증거가 있을 때만 검토한다.
- ECharts 같은 대안을 검토한다면 Waterfall/Heatmap/대규모 데이터/접근성/Bundle Size/SSR·PDF 호환성을 비교한 ADR을 남긴다.
- 같은 제품 안에서 이유 없이 Recharts와 다른 Library를 혼용하지 않는다.

8. Table System
===============================================================================

- 숫자 열은 우측 정렬, Text 열은 좌측 정렬한다.
- 단위는 Header 또는 Table Caption에 둔다.
- 정렬된 열과 방향을 aria-sort와 시각 표시로 함께 표현한다.
- 긴 한글 Header와 Cell은 잘라 숨기지 않고 Wrap 또는 설명 Tooltip을 사용한다.
- HTML에서는 Sticky Header, 검색/정렬, 필요한 경우 Pagination 또는 Virtualization을 사용한다.
- PDF에서는 Header 반복과 명시적 Page Break를 사용한다.
- 이상치·목표 미달·증감 등 의미 있는 경우에만 조건부 서식을 사용한다.
- 색상만으로 상태를 전달하지 않는다.
- Empty는 빈 격자 대신 조건을 바꾸거나 분석으로 돌아가는 다음 행동을 제공한다.
- 좁은 Artifact 폭에서 열을 무리하게 압축하지 않는다. HTML은 명시적 수평 Scroll, PDF는 열 우선순위/다음 페이지/가로 방향 전환 중 하나를 선택한다.
- P0 Table은 읽기 중심이다. Merge/Split/Formula/다중 Cell 편집은 포함하지 않는다.

9. Report Editor UX
===============================================================================

9.1 Editor 구조

- 상단: 보고서 제목, 저장 상태, 방향, 금액 단위, Preview, 확정/PDF
- 좌측 또는 Drawer: Artifact Library와 작성 Block Template
- 중앙: 실제 A4 비율의 Page Canvas
- 우측 또는 Context Inspector: 선택한 Report/Artifact/Block의 제한된 설정
- 1024px급 Tablet에서는 양쪽 Panel로 Canvas를 지나치게 좁히지 않고 하나를 Drawer로 전환한다.

9.2 Artifact Library

- 분석명, 기간, 호텔, 지표, 생성일, 상태로 검색·필터할 수 있다.
- Artifact Card는 제목, 대표 KPI, 기간, 상태, 최신 시점, 미리보기를 제공한다.
- 전체 Artifact Card를 Drag하면 하나의 Artifact Block으로 삽입된다.
- Click 추가는 선택한 Block 아래, 선택이 없으면 문서 끝에 삽입한다.
- 삽입 후 Artifact Block을 선택하고 관련 Inspector를 연다.

9.3 Drag & Drop와 빈 공간 방지

- 자유 좌표 Canvas가 아니라 Page-aware 12-column Grid를 사용한다.
- Drop Target은 위/아래 삽입과 좌/우 분할을 명확히 구분한다.
- 잘못된 영역 Drop은 문서를 바꾸지 않고 취소한다.
- 이동·삭제·Resize 후 중간의 빈 행을 남기지 않고 위로 Compact한다.
- Block끼리 겹치지 않는다.
- 전체 폭 Block 옆에 Drop하면 가능한 경우 6:6으로 자동 재배치한다.
- 한 Block만 남은 행은 기본적으로 전체 폭으로 복귀시킬 수 있다.
- Page 경계를 넘는 Drop에는 다음 페이지 이동 Placeholder를 제공한다.
- 긴 문서 Drag 중 Auto-scroll을 지원한다.
- Editor, 저장 후 재진입, HTML Preview, PDF의 순서와 배치가 일치해야 한다.

9.4 Artifact Block 로컬 도구

- Hover 또는 Selected인 해당 Block에만 Add, Drag Handle, More Menu, Resize Handle을 표시한다.
- More Menu는 해당 Block의 표시 모드, 복제, 위/아래 이동, 너비, 삭제만 바꾼다.
- Artifact Block 표시 모드: 요약형 / 표준형 / 상세형
- Artifact View 표시: KPI, 요약, 각 Chart, Table, 근거 Footer를 안전 범위에서 On/Off
- 너비 Preset: 전체, 1/2, 1/3. Artifact/Chart/Table은 최소 가독 폭 아래로 줄이지 않는다.
- 높이는 내용 기반 Auto를 기본으로 하고, Chart만 안전한 높이 Preset을 제공한다.
- Resize 중 Pointer move마다 History를 쌓지 않고 완료 시 한 Undo 단계만 만든다.

9.5 작성 Block

P0:

- 제목/소제목
- 본문 Markdown
- 핵심 요약/Callout
- 구분선
- 권장 액션 Checklist
- 페이지 나누기
- Artifact

Markdown은 현재 react-markdown + remark-gfm 문자열 계약을 유지한다. Heading, Paragraph, Bullet/Number/Task List, Quote/Callout, Divider, Link, GFM Table, Code 정도를 안정적으로 지원한다. BlockNote/Tiptap으로 Editor 전체를 교체하지 않는다.

9.6 History와 저장

- Add/Delete/Duplicate/Drop/Resize/설정 변경은 각각 정확히 한 History Step이다.
- Text 입력은 매 글자마다 History를 만들지 않고 의미 있는 Editing Transaction으로 묶는다.
- 자동 저장 중, 저장 완료, 저장 실패, 변경 없음을 명확히 구분한다.
- 내부 Navigation, Logout, Session 만료에서 Dirty 경고를 제공한다.
- 동시 수정이 가능하면 revision 기반 Optimistic Concurrency를 사용하고 Server 응답으로 사용자 변경을 덮지 않는다.

9.7 Keyboard와 접근성

- Drag Handle은 Focus 가능한 Button이다.
- Space/Enter로 들기·놓기, 방향키로 이동, Escape로 취소한다.
- 현재 든 Artifact와 Drop 위치를 한국어 Live Region으로 알린다.
- Drag의 대안으로 Block Menu에 위/아래/좌/우 이동을 제공한다.
- Menu는 Arrow/Enter/Escape를 지원하고 닫은 뒤 원래 Handle로 Focus를 돌린다.
- Focus Ring을 Hover 효과에 묻히지 않는다.
- 일반 Text 대비 4.5:1 이상을 지킨다.
- 색상만으로 Selected/Error/변화를 전달하지 않는다.

10. 상태 표현
===============================================================================

분석 결과, Artifact Library, Report Editor, PDF 생성에서 다음 상태를 같은 Design Language로 구분한다.

- Loading: Skeleton + 현재 기다리는 대상
- Empty: 왜 비었는지 + 다음 행동
- Error: 실패 대상 + 재시도 가능 여부 + 대안
- Partial: 볼 수 있는 결과는 유지 + 빠진 범위 표시
- Success/Ready: 과도한 완료 배너 없이 결과 중심
- Stale: 데이터 기준 시각 + 최신 Artifact 확인/교체 action
- Unsupported: 지원하지 않는 Chart/Block/계약임을 명확히 표시
- Saving/Saved/Save failed
- PDF Generating/Final/Generation failed

한 Artifact 실패 때문에 정상 Artifact와 Report 전체를 숨기지 않는다. 다만 FINAL_PDF 확정은 실패 Placeholder를 포함한 채 통과시키지 않는다.

- Template 적용 시 기존 내용을 보존하고 Layout만 안전하게 재배치
- 항목 수와 긴 Label에 따라 열 수를 자동 조절
- 데이터 형태에 맞는 추천 Chart와 제한된 대안 제공
- 데이터에서 도출된 핵심 메시지 후보를 사용자가 선택·편집
- Artifact/Page의 추가·복제·재배치와 자동 저장
- PDF 생성 진행·완료·실패를 명확히 알림
- 동일 역할 전체 설정과 개별 설정을 구분하는 Selection Model은 필요성이 확인될 때 제한적으로 사용

ANSWERVICE에 변형 적용할 패턴:

- PPT Hunter의 수십 개 장식 Template 대신 브랜드가 통제된 소수 Report Preset 제공
- 자유 크기 조절 대신 A4와 데이터 가독성을 지키는 Preset/Minimum Size 제공
- Raw Excel Paste는 Report Editor가 아니라 별도 사용자 데이터 입력 요구가 확정될 때만 검토
- “핵심 메시지 자동 추출”은 검증된 Artifact Fact만 사용하고 LLM 추측을 금지
- 페이지 복제는 Report Version/Artifact 참조를 보존하는 방식으로 구현

가져오지 않을 패턴과 실제 확인된 한계:

- A4 세로로 바꿀 때 기존 3열을 단순히 좁혀 큰 공백과 좁은 Card를 만드는 동작
- Sticky Ribbon이 Direct Edit와 Split Action의 Pointer Event를 가리는 동작
- 22개 Head Template와 매우 많은 Micro-control을 한 화면에 노출하는 복잡도
- 보고서 사용자가 Graphic Designer처럼 임의 좌표로 요소를 미세 이동하는 방식
- PDF Download 전에 개선 의견 Popover를 필수 경로처럼 끼우는 방식
- Chart 종류를 늘리기 위한 장식적 Gauge/Donut 남용
- PPT Hunter의 코드, Asset, 문구를 복사하는 방식. 공개 화면의 Interaction Pattern만 ANSWERVICE에 맞게 재해석한다.

판정:

PPT Hunter는 “형식 선택, 템플릿 탐색, 직접 조작, 다중 페이지, Export” 벤치마크로 유용하다. 그러나 BI 데이터 신뢰성, 접근성, Artifact 계보, 인쇄 안정성의 기준은 아니므로 Power BI와 ANSWERVICE 계약 기준으로 보완해야 한다.

13. 계약과 구현 경계
===============================================================================

이 방향은 Frontend CSS만으로 완성되지 않는다. 다음은 Report Domain 계약이 필요하다.

- Analysis Result와 Artifact의 1:1 Versioned 관계
- Artifact 안의 복수 View와 Unit/Metric Metadata
- Report가 여러 Artifact version을 참조하는 구조
- Draft revision과 Optimistic Concurrency
- Final PDF Snapshot과 수정 불가 상태
- PDF Object, checksum, 생성 상태, 권한
- 기존 1:1 Report Migration

다만 다음은 변경하지 않는다.

- Node2 분석 단계와 응답 구조를 추측해 고정하지 않는다.
- 실제 분석/SQL/Metric 계산 로직을 Report 편의를 위해 바꾸지 않는다.
- Node2가 아직 제공하지 않는 요약·원인·단위를 Production Fake로 채우지 않는다.

[제안] 구현 순서:

Phase 0 — Audit와 ADR
- 현재 OpenAPI, Artifact/Report Schema, 권한, 저장·Preview·Export 경로를 확인
- 이 문서의 개념 모델과 차이를 기록
- Multi-Artifact Report 및 Final PDF ADR 작성

Phase 1 — Frontend-independent UI Foundation
- Versioned Fixture로 AI 요약, Artifact, Multi-Artifact Report 상태를 재현
- Design Token, Chart/Table/KPI, A4 Portrait/Landscape Canvas 완성
- Production 코드에 Fake Data를 넣지 않음

Phase 2 — Multi-Artifact Report Editor
- Artifact Library
- Artifact 전체 Drag & Drop
- Page-aware Grid, Compact, Resize Preset, Undo/Redo
- HTML Draft 저장·재진입·Preview 일치

Phase 3 — Visualization과 Unit
- Artifact 복수 View
- Chart 추천/대안
- Report-level Currency Unit + View Override
- Table/Page Break/Accessibility

Phase 4 — Final PDF
- Preflight
- Version Snapshot
- Deterministic PDF Render
- Final 상태와 새 Draft Version 흐름

Phase 5 — Migration과 실제 E2E
- 기존 N=1 Report 호환
- 권한/IDOR/동시 수정
- 실제 Backend 저장과 PDF Download
- Browser/PDF Visual Regression

한 Phase를 Fixture Screenshot만으로 Production 완료 처리하지 않는다. Phase 1은 UI 기반 완료일 뿐 전체 제품 완료가 아니다.

15. 완료 기준
===============================================================================

제품/계약:

- 분석 결과 1개가 Artifact 1개로 연결되고 Artifact는 복수 View를 가질 수 있다.
- Report 하나에 여러 Artifact version을 저장·재진입 후 동일하게 복원한다.
- 기존 단일 Artifact Report가 깨지지 않는다.
- Final PDF가 확정 revision과 Artifact version을 동결한다.

UI/UX:

- 가로는 Executive Dashboard, 세로는 Narrative Report로 명확히 다르다.
- 첨부 이미지의 정보 계층과 Layout 의도를 ANSWERVICE 색·Typography로 재구성한다.
- Artifact 전체 추가·이동·크기 변경이 직관적이다.
- 이동·삭제·Resize 후 빈 공간, 겹침, 의도치 않은 자동 확장이 없다.
- Block별 Menu와 선택 상태가 해당 Block에만 적용된다.
- HTML Editor와 Preview, 저장 후 재진입, PDF가 일치한다.

Chart/Table/Unit:

- 하나의 Artifact에 목적이 다른 복수 Chart View를 표현할 수 있다.
- Chart마다 제목, 단위, Axis, Legend, Tooltip, 상태, 출처를 읽을 수 있다.
- Table과 Chart의 숫자·단위·반올림이 일치한다.
- 사용자가 Report 금액 단위를 선택할 수 있고 PDF에도 동일하게 반영된다.
- 단위 미확인 값을 추측하지 않는다.

품질:

- Desktop 1440x900과 Tablet 1024x900에서 Editor를 검증한다.
- A4는 mm 기반 Portrait/Landscape PDF로 별도 검증한다.
- Mobile은 수정·검증 범위에서 제외한다.
- 수평 Overflow, Block 겹침, 중간 빈 행, Browser Console Error 0건이다.
- Keyboard-only로 Artifact 추가·이동·Menu·Preview·확정을 수행할 수 있다.
- Frontend Production Build와 Contract Test, 관련 Unit/Integration/E2E가 통과한다.
- PDF를 Page Image로 Render해 HTML Screenshot과 직접 비교한다.
- 실행하지 않은 검증을 통과했다고 보고하지 않는다.

================ REPORT_ARTIFACT_UX_IMPLEMENTATION_PROMPT_START ================

C. 확정 제품 원칙
--------------------------------------------------------------------------

- 보고서 제목에 사용자 자연어 질문 원문을 사용하지 않는다.
- A4 가로는 Executive Dashboard, A4 세로는 Narrative Report다.
- HTML은 구조화된 Block Report의 편집 가능한 Render이며 raw HTML 실행기가 아니다.
- PDF는 확정된 특정 revision의 서비스 내 수정 불가 Snapshot이다.
- Final PDF 수정은 기존 파일 변경이 아니라 새 Draft Version 생성이다.
- Artifact 전체가 Report Editor에서 하나의 Drag & Drop Block이다.
- Artifact는 같은 분석 결과의 복수 Chart View를 포함할 수 있다.
- Report는 여러 Artifact version을 포함한다.
- Artifact 원본 Fact와 Evidence를 Report 편집으로 변조하지 않는다.
- Report-level 금액 단위와 제한된 View Override를 제공한다.
- 단위가 계약으로 확인되지 않으면 추측하지 않는다.
- 기존 ANSWERVICE 색과 브랜드는 유지하되, A4 Canvas는 인쇄 가능한 밝은 종이 표면으로 설계한다.
- Mobile은 수정·검증하지 않는다.

   - 추이/구성비/범주 비교 Chart 3개
   - 핵심 인사이트 + 권장 액션
   - 출처/생성 근거 Footer

   A4 세로 기본:
   - Header
   - 핵심 요약
   - KPI
   - Chart/Table
   - 주요 변화 분석
   - 권장 액션
   - 출처/근거/Footer

3. 두 방향을 폭만 바꾼 같은 Layout로 만들지 않는다.
   긴 Label과 많은 콘텐츠를 실제 Fixture로 넣어 열 수, Page Break, 순서를 검증한다.

4. 1440x900과 1024x900은 Editor Viewport 기준이다.
   A4 출력은 210x297mm / 297x210mm와 @page 기준으로 별도 구현·검증한다.

5. 새 CSS를 파일 끝에 계속 덧붙이지 않는다.
   대상 화면의 충돌 규칙과 !important를 찾아 필요한 범위에서 정리한다.

--------------------------------------------------------------------------
F. Analysis Result와 Artifact
--------------------------------------------------------------------------

- AI 답변형 요약과 상세 분석 결과 Artifact를 분리한다.
- AI 답변은 제목, 3개 이하 요약, 핵심 KPI, 대표 Chart, 조건/최신 시점, 근거 진입점, 후속 행동을 제공한다.
- Artifact는 Summary, KPI, 복수 View, 상세 Table, 조건, Evidence, Limitation을 제공한다.
- “분석 과정 완료” 메시지를 결과보다 강조하지 않는다.
- READY/PARTIAL/STALE/EMPTY/ERROR/UNSUPPORTED를 시각적으로 구분한다.
- 첫 KPI를 근거 없이 Primary로 강조하지 않는다.
- 5개 이상 Series를 조용히 버리지 않는다. 제한 시 개수와 이유를 알리고 Table 대안을 제공한다.

--------------------------------------------------------------------------
G. Chart와 Table
--------------------------------------------------------------------------

- 기존 Recharts와 EnterpriseChart를 먼저 사용한다.
- ResponsiveContainer, Custom Tooltip/Legend, Axis, Unit, Data Label, accessibilityLayer를 실제로 완성한다.
- P0 Chart: KPI, Line/Area, Horizontal/Vertical Bar, Grouped/Stacked/100% Stacked, Donut, Scatter, Bar+Line.
- Waterfall/Bullet/Heatmap은 실제 요구와 Recharts 한계를 재현한 뒤 ADR로 결정한다.
- 새 Library는 기존 도구로 해결할 수 없는 문제를 입증한 경우에만 추가한다.
- Chart 제목, 기간, 단위, Legend, Axis, Tooltip, Source, Freshness, Empty/Error/Partial을 모두 검증한다.
- 같은 Metric/Category 색을 일관되게 유지한다.
- Table은 숫자 우측 정렬, Unit Header, aria-sort, 긴 한글 Wrap, Sticky/Repeat Header, Empty/Error를 갖는다.
- Chart의 동일 데이터 Table 대안을 제공한다.

--------------------------------------------------------------------------
H. Currency와 Number Formatting
--------------------------------------------------------------------------

- Report 기본 단위: 자동/원/천 원/만 원/백만 원/억 원.
- 신뢰 가능한 원본 Unit -> Report Unit -> View Override 순서를 지킨다.
- 원본 값은 바꾸지 않고 Display Scale만 바꾼다.
- Tooltip/상세 Table에서 정확한 원값을 제공한다.
- 0/null/데이터 없음/계산 불가/Error를 구분한다.
- %와 %p를 구분한다.
- HTML Preview와 PDF의 단위·반올림·Separator가 일치한다.
- Unit 미확인은 Final PDF Preflight를 막는다.

--------------------------------------------------------------------------
I. Report Editor
--------------------------------------------------------------------------

- Artifact Library에서 Artifact 전체를 Drag해 원하는 Page/위치에 삽입한다.
- Drop Guide는 위/아래와 좌/우 분할을 명확히 구분한다.
- Page-aware 12-column Grid를 유지한다.
- 이동/삭제/Resize 뒤 빈 행과 겹침을 제거한다.
- 전체 폭 옆 Drop은 가능한 경우 6:6으로 자동 조정한다.
- 사용자가 선택한 크기를 이유 없이 저장/재진입 시 바꾸지 않는다.
- Editor, 저장 후 재진입, HTML Preview, PDF가 같은 순서·Layout을 보여야 한다.
- Artifact Block마다 독립된 Add/Drag/Menu/Resize 도구를 제공한다.
- 표시 모드 요약형/표준형/상세형과 안전한 너비/높이 Preset을 제공한다.
- Add/Delete/Duplicate/Drop/Resize/설정 변경은 각각 한 Undo Step이다.
- 긴 문서 Drag Auto-scroll과 잘못된 Drop 취소를 지원한다.
- Keyboard Drag, 대체 이동 Menu, 한국어 Live Announcement를 제공한다.
- Tablet에서는 Hover-only Control을 금지하고 선택 Block 도구를 보이게 한다.

--------------------------------------------------------------------------
J. HTML -> PDF
--------------------------------------------------------------------------

- Draft/Review-ready/Confirming/PDF-generating/Final/Failed 상태를 구현한다.
- Finalize 전에 제목, Unit, Artifact version, Error Placeholder, Overflow, Page Break, Font, Source를 Preflight한다.
- PDF 생성 실패를 Success로 표시하지 않는다.
- PDF는 확정 revision과 Artifact version을 동결하고 checksum을 기록한다.
- Final PDF에서 편집 기능을 제거하고 “새 버전으로 편집”만 제공한다.
- Portrait/landscape Page Size와 Page Count를 실제 PDF로 검증한다.
- Table Header 반복, Footer, 페이지 번호, 한글 Font, Chart 잘림을 Page Image에서 확인한다.
