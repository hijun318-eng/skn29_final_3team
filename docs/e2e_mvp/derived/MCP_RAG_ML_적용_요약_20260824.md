## 1. 한눈에 보기

Backend에 MCP 표준 호출 경로를 추가하고 기존 RAG와 ML 실행 기능을 Tool로 연결했다.

```text
사용자 로그인
→ MCP initialize
→ tools/list
→ tools/call
→ RAG 또는 ML 실제 실행
→ 결과 반환
→ PostgreSQL 감사 이력 저장
```

현재 등록된 MCP Tool은 3개다.

| Tool | 역할 |
|---|---|
| `analysis.get_run` | 저장된 분석 실행 결과 조회 |
| `rag.answer` | 내부 매뉴얼 기반 RAG 답변 조회 |
| `ml.predict` | 승인된 객실 점유율 예측 실행 |

## 2. 적용한 내용

### MCP

- `initialize`, `tools/list`, `tools/call` 요청 처리
- DB Tool Registry에서 활성화된 Tool만 사용
- Tool마다 입력 형식 검증
- 목록 조회와 실제 호출에 같은 권한 정책 적용
- 성공, 실패, 거부 결과를 PostgreSQL 감사 이력으로 저장

### RAG

- MCP Tool 이름을 `rag.answer`로 통일
- 기존 내부 매뉴얼 Agent를 MCP 호출 경로에 연결
- 실제 RAG API 결과와 인용 근거를 반환

### ML

- MCP Tool 이름을 `ml.predict`로 통일
- 호텔 코드, 지표, 예측 기간을 형식 검증한 뒤 기존 ML Runtime 호출
- 현재 승인 범위는 `OCCUPANCY_RATE`, 예측 기간 1~7일
- 실제 Trino PMS 데이터를 사용한 모델 결과와 실행 근거 반환

## 3. 현재 권한 정책

현재 설정은 다음과 같다.

```text
MCP_ROLE_ENFORCEMENT_ENABLED=false
```

따라서 로그인한 네 역할 모두 MCP Tool을 보고 호출할 수 있다.

| 현재 역할 | MCP/ML 사용 |
|---|---|
| `analyst` | 허용 |
| `report_admin` | 허용 |
| `data_admin` | 허용 |
| `platform_admin` | 허용 |

향후 제한이 필요하면 설정을 `true`로 변경한다. 이때 ML은 다음 역할만 허용된다.

| 업무 역할 | 현재 코드 역할 | 제한 모드 ML 사용 |
|---|---|---|
| 객실수요담당자 | `analyst` | 허용 |
| 시스템관리자 | `platform_admin` | 허용 |
| 보고서담당자 | `report_admin` | 차단 |
| 데이터담당자 | `data_admin` | 차단 |

별도의 `room_demand_manager` 역할은 아직 추가하지 않았다. 현재 시스템의 `analyst`가 객실수요담당자를 나타낸다.

## 6. 운영 시 주의사항

- 공개 대상은 익명 사용자가 아니라 정상 로그인한 사용자다.
- `MCP_ROLE_ENFORCEMENT_ENABLED=true`로 바꾸면 ML 역할 제한이 즉시 적용된다.
- 기존 마이그레이션 `20260824_36`을 수정하지 말고 `20260824_37`까지 순서대로 적용한다.
- 인증 비밀번호, API Key, 세션 비밀값은 문서나 Git에 저장하지 않는다.
- MCP 호출에는 서버가 요구하는 프로토콜 버전과 헤더를 정확히 전달해야 한다.
