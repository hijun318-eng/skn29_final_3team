## 2. 프로젝트 한눈에 보기

### 한 줄 정의

Answervice는 사용자가 자연어로 기업 내부 데이터를 질문하면 승인된 업무 기준과 권한 안에서 데이터를 교차 분석하고, 검증된 결과와 근거를 보고서까지 연결하는 서비스다.

### 해결하려는 문제

- 업무 데이터가 여러 시스템에 흩어져 있어 하나의 질문에도 수작업 취합이 필요하다.
- 같은 지표와 기간도 부서마다 해석이 달라 결과가 어긋날 수 있다.
- AI 답변만으로는 사용 데이터, 계산 기준과 권한 준수 여부를 확인하기 어렵다.
- 일회성 분석 결과가 저장·재실행·보고서로 자연스럽게 이어지지 않는다.

### 핵심 해결 방식

1. 자연어 질문에서 지표, 기간, 필터와 분석 목적을 파악한다.
2. 모호한 지표나 기간은 실행 전에 사용자에게 확인한다.
3. 사용자 권한 안에서 승인된 데이터와 업무 규칙만 분석 범위로 구성한다.
4. 여러 데이터 원천을 읽기 전용으로 연결해 분석한다.
5. 실행 전후 검증을 통과한 결과만 표·차트·설명·근거로 제공한다.
6. 검증된 분석을 저장·재실행하고 보고서 작성과 실행에 재사용한다.

### 기대 가치

- 현업 사용자는 데이터 구조를 몰라도 업무 용어로 분석을 시작할 수 있다.
- 의사결정자는 결과와 함께 기간, 출처, 적용 기준과 검증 근거를 확인할 수 있다.
- 반복 분석과 보고서 갱신 과정에서 기준과 이력을 유지할 수 있다.
- AI가 데이터 권한과 실행 허용 여부를 임의로 결정하지 않도록 통제할 수 있다.

## 3. 추진 배경과 문제 정의

### 기존 업무 방식의 문제

객실, 식음, 회원, 시설과 연회 데이터는 서로 다른 시스템에 존재한다. 교차 분석을 하려면 담당자가 각 시스템에서 자료를 추출하고 기간과 연결 기준을 수작업으로 맞춰야 한다. 지표 정의가 다르면 같은 질문에도 다른 답이 만들어진다.

기존 AI 질의 도구는 빠른 답을 줄 수 있지만, 어떤 데이터와 규칙을 사용했는지 또는 권한을 지켰는지 확인하기 어렵다. 근거가 없는 답은 실제 업무에서 재사용하거나 승인하기 어렵다.

### 사용자 불편

- 현업 사용자는 새로운 질문마다 데이터 담당자에게 추출을 요청한다.
- 담당자 간 지표·기간 해석 차이로 재작업이 발생한다.
- 결과 수치와 근거를 별도로 확인해야 한다.
- 지난 분석을 새 기간으로 반복하거나 보고서로 옮길 때 기준이 분리된다.

### 새로운 제품이 필요한 이유

고정 KPI 반복 조회는 기존 BI가 더 적합하다. Answervice는 기존 화면에 없는 질문, 여러 업무 영역을 연결하는 질문, 결과를 분석 자산과 보고서로 재사용해야 하는 상황에 집중한다.

## 4. 목표 사용자

| 사용자 유형 | 주요 목적 | 현재 어려움 | 제공 가치 |
|---|---|---|---|
| 사업책임자·의사결정자 | 여러 업무 영역의 변화를 비교하고 판단 근거를 확인한다. | 데이터가 흩어져 있고 기존 대시보드만으로 새 질문에 답하기 어렵다. | 자연어 교차 분석과 표·차트·설명·근거를 함께 확인한다. |
| 현업 분석 담당자 | 새로운 질문에 답하고 반복 분석을 갱신한다. | 지표·기간·연결 기준을 매번 확인하고 결과를 다시 정리한다. | 승인된 기준으로 분석하고 저장·재실행한다. |

| 데이터·시스템 담당자 | 데이터 경로, 업무 규칙, 권한과 품질을 관리한다. | 분석 요청마다 허용 범위와 연결 기준을 반복 검토한다. | 승인 기준을 일관되게 적용하고 감사 근거를 남긴다. |

제품의 주요 역할은 현업 분석 담당자와 보고서 관리자다. 데이터·시스템 담당자를 위한 전체 관리 화면은 제품 범위에서 제외한다.

## 5. 제품 목표와 비목표

### 제품 목표

1. 승인된 업무 용어와 기간으로 자연어 분석을 시작할 수 있게 한다.
2. 여러 업무 데이터가 필요한 대표 질문을 하나의 흐름에서 처리한다.
3. 모호한 질문은 임의로 실행하지 않고 사용자 확인을 받는다.
4. 권한·업무 규칙·읽기 전용 원칙으로 허용된 분석만 실행한다.
5. 검증된 결과를 표·차트·설명과 근거로 제공한다.
6. 분석 정의, 개별 실행과 결과를 분리해 저장·재실행·이력 조회를 지원한다.
7. 분석 결과를 보고서로 재사용하고 승인·실행·부분 실패를 관리한다.

### 이번 범위에서 하지 않는 것

- 모든 데이터베이스, 지표, 연결 방식과 자연어 질문의 자동 지원
- 등록되지 않은 지표와 연결 규칙의 AI 임의 생성
- 실제 기업 IAM·SSO와 전체 개인정보·보안 체계 구현
- 데이터 카탈로그 전용 관리 화면과 고급 감사 대시보드
- 합성 데이터 검증 결과를 실제 기업 성능·안전성으로 일반화

### 기존 BI가 더 적합한 영역

- 이미 정의된 KPI를 같은 형태로 반복 조회하는 업무
- 실시간 모니터링과 고정 대시보드 중심 업무
- 변경 없는 전사 표준 보고서 배포

## 8. 핵심 사용자 시나리오

### 자연어로 교차 분석한다

사용자가 기간과 업무 지표를 포함해 여러 영역의 매출 변화를 질문한다. 제품은 권한과 승인 기준을 확인하고 데이터를 연결해 검증된 결과와 근거를 제공한다.

### 모호한 질문을 보완한다

지표나 기간을 하나로 확정할 수 없으면 제품은 실행을 멈추고 승인된 선택지나 보완 내용을 안내한다. 사용자가 의미를 확정하면 새 분석을 시작한다.

### 분석을 저장하고 재실행한다

사용자는 검증된 분석을 저장하고 이후 기간 등 허용된 조건을 바꾸어 다시 실행한다. 새 실행은 현재 권한과 규칙을 다시 확인하며 과거 결과를 덮어쓰지 않는다.

### 보고서를 만들고 실행한다

사용자는 검증된 분석에서 보고서 초안을 만들고 블록을 편집한다. 관리자는 버전을 승인·실행하며 일부 블록 실패를 전체 성공과 구분한다.

### 반복 보고를 예약하거나 작성 지원을 받는다

관리자는 승인 보고서의 반복 실행을 예약할 수 있다. 작성 지원은 검증된 분석 근거로 편집 가능한 초안을 제안하지만 자동 승인하거나 데이터를 다시 계산하지 않는다.

## 9. 서비스 이용 방식

1. 사용자는 로그인하고 역할에 허용된 기능을 이용한다.
2. 업무 용어, 분석 대상과 기간을 포함한 자연어 질문을 입력한다.
3. 지표나 기간이 모호하면 승인된 기준을 선택하거나 질문을 보완한다.
4. 제품은 권한 안에서 필요한 데이터와 업무 규칙만 구성한다.
5. 분석 조건, 실행 안전성과 결과 공개 가능성을 순서대로 검증한다.
6. 사용자는 표·차트·설명과 기간·지표·출처·검증 근거를 확인한다.
7. 검증된 분석을 저장·재실행하거나 보고서 초안으로 활용한다.
8. 보고서 관리자는 버전을 승인하고 수동 또는 예약 실행 결과를 확인한다.

실패하거나 검증되지 않은 결과는 과거 성공 결과나 샘플 데이터로 대체하지 않는다.

## 10. 전체 서비스 구조

~~~mermaid
flowchart LR
    U["사용자"] --> F["사용자 화면"]
    F --> B["서비스 제어\n인증·권한·상태"]
    B --> A["AI 분석\n질문 해석·생성·설명"]
    B --> C["승인 기준\n데이터·지표·업무 규칙"]
    A --> V["단계별 검증"]
    C --> V
    V --> D["읽기 전용 데이터 조회"]
    D --> V
    V --> S["분석·근거 저장"]
    S --> F
    S --> R["보고서\n편집·승인·실행"]
    R --> F
~~~

- 사용자 화면은 질문, 진행 상태, 결과·근거와 보고서 작업을 제공한다.
- 서비스 제어 영역은 인증·권한과 분석의 시작·중단·완료를 통제한다.
- AI는 질문 해석, 질의 후보와 설명을 지원하지만 권한을 결정하지 않는다.
- 승인 기준과 단계별 검증은 사용할 데이터와 실행·공개 가능 범위를 제한한다.
- 데이터 조회는 업무 원천을 읽기 전용으로 연결한다.
- 저장 영역은 분석 정의·실행·결과·근거를 보존하고 보고서가 이를 참조한다.

상세 연결 방식은 [아키텍처 문서](03_아키텍처.md)에서 관리한다.

## 11. 성공 기준

### 기능 성공 기준

- 대표 자연어 질문이 승인된 여러 데이터 원천의 검증 결과로 이어진다.
- 모호한 질문은 실행 전에 사용자 확인으로 전환된다.
- 권한 밖·쓰기 성격·근거 부족 요청은 결과 공개 전에 차단된다.
- 결과가 표·차트·설명·출처·검증 근거와 함께 제공된다.
- 분석 저장·새 실행·과거 결과 보존과 보고서 활용이 이어진다.
- 보고서 일부 실패가 전체 성공으로 표시되지 않는다.

### 사용자 가치 기준

- 사용자가 데이터 구조를 몰라도 승인된 업무 질문을 시작할 수 있다.
- 결과가 어떤 기간·지표·데이터와 검증을 거쳤는지 확인할 수 있다.
- 저장 분석과 보고서를 반복 업무에 재사용할 수 있다.

### 품질·안전 기준

- AI가 권한과 실행 허용 여부를 결정하지 않는다.
- 업무 원천은 읽기 전용으로 조회한다.
- 실패를 성공 또는 과거 결과로 대체하지 않는다.
- 과거 실행과 결과를 덮어쓰지 않고 감사 근거를 연결한다.

### 검증 방법

정상 질문뿐 아니라 모호성, 권한 거부, 쓰기 시도, 외부 의존성 장애, 취소와 일부 실패를 자동 검증과 실제 사용자 경로에서 확인한다. 근거 없는 정확도·성능·비용 목표는 사용하지 않는다.

## 12. 제약사항과 위험

| 제약·위험 | 영향 |
|---|---|
| 합성 데이터 | 실제 기업 데이터의 분포·품질·민감도와 운영 조건을 대표하지 못한다. |
| 승인 범위 제한 | 등록되지 않은 지표·데이터·연결 규칙의 질문은 지원하지 못한다. |
| 외부 모델·데이터 플랫폼 의존 | 서비스 장애나 계약 불일치 시 분석이 중단된다. |
| 메타데이터와 업무 기준 불일치 | 분석이 잘못 차단되거나 승인 범위를 신뢰하기 어려워질 수 있다. |
| 데모 수준 인증·권한 | 실제 기업 IAM·SSO와 개인정보 정책을 대체하지 못한다. |
| 운영 준비 | 장시간·대규모 부하, 복구와 외부 운영 배포는 별도 검증이 필요하다. |

## 13. 용어 정리

| 용어 | 의미 |
|---|---|
| 승인 컨텍스트 | 한 질문과 사용자에게 허용된 데이터·지표·기간·연결 규칙의 최소 분석 범위 |
| 분석 전 조건 검증 | 필요한 데이터, 지표, 기간, 연결 규칙과 권한이 준비됐는지 확인하는 단계 |
| 실행 안전성 검증 | 읽기 전용 여부와 승인된 데이터·규칙 준수 여부를 확인하는 단계 |
| 결과 검증 | 결과 구조, 크기, 민감정보와 근거를 확인해 공개 가능 여부를 결정하는 단계 |
| 분석 정의 | 반복 실행할 수 있도록 저장한 분석의 목적과 조건 |
| 분석 실행 | 특정 시점과 조건으로 수행한 한 번의 분석 |
| 분석 결과 자산 | 검증 결과, 표·차트·설명과 근거를 묶은 저장 단위 |
| 보고서 버전 | 편집 가능한 초안 또는 변경이 제한된 승인본 |
| 일부 성공 | 여러 데이터 영역이나 보고서 블록 중 일부만 성공한 상태 |
| MCP | 외부 도구가 승인된 제품 기능을 이용하는 연동 규격. 현재 범위는 제한된 읽기 조회다. |

이 기획서는 제품 방향과 범위를 설명한다. 기능별 완료 조건은 [PRD](01_PRD.md), 사용자 목적별 과정은 [유저 플로우](02_유저플로우.md), 구현 구조와 연결 이유는 [아키텍처](03_아키텍처.md)에서 관리한다.
