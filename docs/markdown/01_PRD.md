# Answervice 제품 요구사항 문서(PRD)

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 문서 목적 | Answervice에서 무엇을 구현하고 검증해야 하는지 독립적인 제품 기능 단위로 정의한다. |
| 대상 독자 | 기획자, 제품 책임자, 개발자, QA, 데이터·시스템 담당자, 평가자 |
| 기준일 | 2026-08-14 |
| 완료 표현 | 각 요구사항을 현재 근거에 따라 Yes 또는 No로만 판정한다. |
| 제품 성격 | 범용 기업 내부 데이터 분석·리포팅 서비스 |
| 검증 환경 | 호텔·리조트 운영 합성 데이터 |

### 근거와 문서 경계

- [기획서](00_기획서.md), [E2E 기준 문서](e2e_mvp/README.md)와 실제로 연결되는 PRD·유저 플로우·아키텍처·진행 기록
- 현재 사용자 화면, 분석·보고서·데이터 연동 코드와 관련 테스트

이 문서는 관찰 가능한 제품 결과와 완료 조건을 정의한다. API, 데이터 구조, 클래스·함수, 라이브러리와 내부 처리 단계는 설계·기술 문서에서 관리한다. 기존 요구사항 정의서는 재작성 범위와 충돌할 수 있어 근거로 사용하지 않았다.

## 2. 제품 범위

### 2.1 P0 핵심 범위

- 인증, 세션과 역할별 접근
- 자연어 질문과 지표·기간 명확화
- 승인된 데이터·업무 규칙과 읽기 전용 분석
- 실행 진행, 취소와 오류 상태
- 표·차트·설명과 분석 근거
- 분석 저장, 재실행과 과거 이력 보존
- 분석 결과 기반 보고서 초안·편집·승인·수동 실행
- 보고서 부분 실패
- 감사 추적, 재현성, 보안과 영속성
- 대표 사용자 흐름과 고정 평가 세트를 사용한 검증

### 2.2 P1 확장 범위

- 일정 기반 보고서 실행
- 검증된 분석 근거를 사용한 보고서 작성 지원
- 인증된 사용자의 저장된 분석을 조회하는 제한된 MCP 읽기 전용 연동

P1 기능은 핵심 MVP와 분리해 관리한다. 코드가 존재하거나 과거 실행 기록이 있더라도 현재 검증에서 실패한 기능은 완료를 No로 판정한다.

### 2.3 후순위 또는 제외 범위

- 검색 증강 생성(RAG)
- ML-as-a-Tool
- 승인되지 않은 임의 지표·데이터·연결 규칙 자동 생성
- 모든 데이터베이스와 모든 자연어 질문의 범용 지원
- 실제 기업 IAM·SSO 전체 구현
- 데이터 카탈로그 전용 관리 화면
- 고급 감사·운영 대시보드
- 대규모 부하와 장시간 운영 검증
- 외부 운영 환경 배포

## 3. 사용자와 권한

| 사용자 유형 | 제품에서의 목적 | 허용 범위 | 제한 범위 |
|---|---|---|---|
| 사업책임자·의사결정자 | 여러 업무 영역의 변화와 의사결정 근거를 확인한다. | 분석 결과와 보고서 소비 | 데이터 구조나 권한 정책 직접 변경 |
| 현업 분석 담당자 | 자연어 분석을 수행하고 결과를 저장·재실행하며 보고서 초안을 만든다. | 분석, 실행 이력, 본인 분석 기반 보고서 초안 | 보고서 최종 승인·실행·예약 관리 |
| 보고서 관리자 | 보고서 버전, 승인, 수동·예약 실행을 관리한다. | 보고서 관리 기능 | 자연어 분석 실행 |
| 데이터·시스템 담당자 | 승인 데이터, 업무 지표, 연결 규칙과 운영 기반을 관리한다. | 제품 신뢰 기반 관리 | 전용 관리 화면 전체는 현재 제품 범위가 아님 |
| 외부 도구 사용자 | 승인된 표준 연동으로 본인의 저장된 분석 실행을 조회한다. | 제한된 읽기 전용 조회 | 쓰기, 타인 실행 조회, 미등록 기능 호출 |

현재 런타임에서 직접 구분되는 대표 역할은 현업 분석 담당자와 보고서 관리자다. 사업책임자와 데이터·시스템 담당자는 제품 목적을 정의하는 사용자·이해관계자이며, 모든 전용 화면이 구현된 것으로 간주하지 않는다.

## 4. 요구사항 작성 및 완료 판정 규칙

### 작성 원칙

- 요구사항 하나는 하나의 사용자 결과 또는 검증 대상만 포함한다.
- 독립적으로 실패할 수 있는 동작은 분리하고, 버튼·탭·함수 호출 같은 구현 단위는 요구사항으로 만들지 않는다.
- 인수 조건은 화면, 저장 이력 또는 테스트로 참·거짓을 판단할 수 있어야 한다.
- 측정 근거 없는 표현·성능 수치와 구현 방법은 사용하지 않는다.

### Yes/No와 우선순위

| 완료 | 판정 기준 |
|---|---|
| Yes | 현재 코드가 존재하고 관련 현재 테스트가 통과했거나, 코드와 날짜가 명확한 실제 실행 근거가 함께 확인된다. |
| No | 구현이 없거나 일부만 존재하거나, 현재 검증이 실패했거나, 완료를 증명할 근거가 부족하다. |

부분 구현이거나 현재 관련 실패가 확인되면 No다. 실행하지 않은 외부 서비스·배포 경로는 통과로 선언하지 않는다.

| 우선순위 | 의미 |
|---|---|
| Must | P0 사용자 흐름, 안전 경계 또는 완료 판정에 필수 |
| Should | 핵심 MVP 완료 후 제공하는 P1 확장 기능 |
| Could | 별도 운영 범위와 일정 합의 후 진행할 후속 기능 |

### 8.4 주요 미완료 또는 재검증 필요 영역

6. **전체 P0**: 모든 P0 No 항목이 해소되기 전에는 완료로 판정하지 않는다.

이 PRD는 제품이 제공해야 하는 결과와 현재 완료 판정을 관리한다. 사용자 목적별 전체 과정은 유저 플로우, 화면별 상세 구성은 화면 설계서, 구현 방식과 데이터·연동 구조는 별도의 설계·기술 문서, 실제 수행 작업과 일정은 WBS에서 관리한다.
