## 1. 목적과 범위

Answervice는 호텔 내 분산된 운영 데이터와 DataHub 메타데이터를 연결하고, 자연어 질문을 결정론적 Gate가 통제하는 읽기 전용 분석과 재현 가능한 자동 보고서로 변환한다. DataHub는 메타데이터 기준 시스템, Trino는 읽기 전용 연합 조회 엔진, FastAPI Controller는 상태 전이와 G1·G2·G3를 통제하는 Control Plane으로 사용한다.

### 1.1 우선순위

| 구분 | 범위 | 완료 판단 |
|---|---|---|
| P0 | 합성 데이터, 인증·권한, Context, Guarded Text-to-SQL, 결과·근거·Artifact, 보고서 정의·수동 실행·이력·감사 | I1~I4 계약과 통합 Gate에서 소비 가능한 산출물 및 검증 증거 확보 |
| P1 | 5개 논리 소스 ingestion·카탈로그·연결 상태, Context 승인·버전, 스케줄 활성화 | P0 수동 경로 안정화 후 승인된 계약과 권한 안에서 검증 |
| P2 | MCP, 문서 RAG, ML-as-a-Tool, 외부 Report 배포 | R1의 별도 편입 결정 전 구현 범위 제외 |
| 선택 | 고객 360 | identity mapping·masking·전용 권한·일정 영향 승인 전 구현 범위 제외 |

### 1.2 사용자 역할

| 역할 | 주요 권한 |
|---|---|
| 일반 사용자 | 승인 범위의 질문·결과·근거 확인, Artifact 생성, 보고서 열람 |
| 관리자 | 보고서 정의 편집·승인, 수동 실행, Gate 통과 후 스케줄 관리 |
| 데이터·시스템 관리자 | 자산·Context·연결·권한·서비스 상태와 감사 추적 관리 |
| 감사자 | 권한·정책·실행 증적의 읽기 전용 검색·내보내기 |
| 선택 범위 사용자 | 고객 360 편입 승인 후 마스킹된 고객 단위 내부 분석 |

내부 role 식별자와 사용자·그룹 mapping은 I1의 versioned `access-policy.yaml` 및 DB migration 계약에서 확정하며 이 문서에서 임의로 고정하지 않는다.

## 4. 추적 및 변경 통제

- 요구사항의 일정·담당·현황은 `02_WBS.md`를 기준으로 한다.
- 화면 ID, route, 상태와 접근성 상세는 `05_화면설계서.md`를 기준으로 하되 본 요구사항과 충돌하면 R1이 계약 결정을 기록한다.
- 구현은 `Gate_실행_카드_원장.md`에서 `READY`로 발행된 실행 묶음의 카드와 허용 경로 안에서만 수행한다.
- 요구사항 ID는 삭제하거나 재사용하지 않는다. 폐기 시 행을 제거하지 않고 상태·대체 ID·근거를 변경 내역에 기록한다.
- P2와 선택 범위는 R1의 편입 결정, 요구사항·수용 기준, WBS와 실행 묶음이 함께 갱신된 뒤 시작한다.
