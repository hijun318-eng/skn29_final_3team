# Answervice 유저 플로우

## 1. 문서 개요

이 문서는 사용자가 하나의 업무 목적을 달성하는 시작부터 종료까지를 설명한다. 질문 제출, 분석 저장·재실행, 보고서 편집처럼 큰 시나리오를 플로우로 정의하며 버튼 클릭이나 단순 목록 조회는 별도 플로우로 만들지 않는다.

| 항목 | 내용 |
|---|---|
| 대상 사용자 | 현업 분석 담당자, 사업책임자, 보고서 관리자, 승인된 외부 도구 사용자 |
| 제품 범위 | P0 분석·보고서 흐름과 P1 예약·작성 지원·MCP 읽기 연동 |
| 기준 | E2E 기준 문서와 PRD의 제품 범위·요구사항 |
| 기술 경계 | API, DB, 함수·컴포넌트와 내부 호출 순서는 제외 |

기능별 구현·완료 상태는 PRD에서 관리한다. 호텔·리조트는 합성 데이터로 검증하는 도메인이며 실제 고객 운영 환경이 아니다.

## 2. 공통 사용자와 역할

| 역할 | 주요 목적 | 접근 범위 |
|---|---|---|
| 현업 분석 담당자 | 자연어 분석, 저장·재실행, 보고서 초안 작성 | 본인 분석과 본인 소유 자산 |
| 사업책임자 | 분석·보고서 결과와 근거 확인 | 제공된 결과 소비 |
| 보고서 관리자 | 보고서 버전 검토, 승인, 수동·예약 실행 | 보고서 관리 기능 |
| 승인된 외부 도구 사용자 | 본인의 저장 분석을 외부 도구에서 조회 | 제한된 읽기 전용 기능 |

화면의 메뉴 제한은 사용자 경험을 위한 장치이며 최종 권한은 서비스가 판단해야 한다.

## 3. 공통 시작 조건

- 사용자는 유효한 세션으로 인증되어 있어야 한다.
- 역할에 허용된 화면과 기능만 이용해야 한다.
- 필수 저장소, 메타데이터, 통합 조회와 모델 서비스가 해당 흐름에 필요한 상태여야 한다.
- 분석은 승인된 데이터·지표·업무 규칙과 읽기 전용 권한 안에서 수행한다.
- 실제 고객 데이터가 아닌 합성 호텔·리조트 데이터를 사용한다.

## 5. UF-01. 자연어 질문으로 분석 결과와 근거 얻기

- **사용자 목적:** 여러 업무 데이터를 연결한 검증 결과와 판단 근거를 얻는다.
- **주요 사용자:** 현업 분석 담당자, 사업책임자
- **관련 요구사항 ID:** FR-ANL-001~003, FR-ANL-008~013, FR-CTX-001~004, FR-RES-001~008
- **시작 조건:** 분석 담당자로 로그인했고 질문에 하나로 해석 가능한 지표와 기간이 있다.
- **시작점:** 자연어 질문 제출
- **종료 조건:** 검증 결과와 근거가 표시되거나 성공 결과 없이 명시 상태로 종료

### 기본 흐름

1. 사용자는 업무 지표와 기간을 포함한 질문을 제출한다.
2. 제품은 지표와 기간을 하나의 의미로 확정한다.
3. 제품은 사용자 권한 안에서 승인된 데이터와 업무 기준만 구성한다.
4. 제품은 분석 조건과 읽기 전용 실행 가능 여부를 확인한다.
5. 제품은 진행 상태를 보여주며 필요한 업무 데이터를 조회한다.
6. 제품은 결과 구조, 민감정보, 크기와 근거를 검증한다.
7. 제품은 표·차트·설명과 기간·지표·출처·검증 근거를 표시한다.
8. 제품은 실행 상태와 결과 근거를 이력으로 보존한다.

### 대안 흐름

- 결과가 비어 있으면 임의의 0이나 행을 만들지 않고 빈 결과로 표시한다.
- 일부 데이터 영역만 성공하면 성공·실패 영역을 구분한다.

### 실패·차단 흐름

- 모호한 질문은 UF-02로 전환한다.
- 권한·업무 기준·읽기 전용 조건이 부족하면 조회 전에 차단한다.
- 모델·조회·검증·저장 실패 또는 취소를 성공 결과로 대체하지 않는다.

### 사용자에게 제공되는 결과

검증된 표·차트·설명, 분석 기준·출처·검증 상태와 추적 가능한 실행 근거를 제공한다.

### 완료 기준

- 결과의 기간·지표·출처가 저장된 실행 근거와 일치한다.
- 실패·취소·차단 상태에서 새 성공 결과가 생성되지 않는다.

## 6. UF-02. 모호한 질문을 보완하여 분석 완료하기

- **사용자 목적:** 모호한 지표나 기간을 승인된 기준으로 명확히 해 분석을 완료한다.
- **주요 사용자:** 현업 분석 담당자
- **관련 요구사항 ID:** FR-ANL-004~007, FR-CTX-003, FR-RES-007
- **시작 조건:** 질문의 지표 또는 기간을 하나로 확정할 수 없다.
- **시작점:** 제품이 사용자 확인 필요 상태를 표시
- **종료 조건:** 보완된 새 질문으로 UF-01을 완료하거나 보완 없이 종료

### 기본 흐름

1. 제품은 모호한 질문을 임의 기준으로 실행하지 않는다.
2. 지표와 기간 중 어떤 항목의 확인이 필요한지 안내한다.
3. 지표가 모호하면 사용자 권한 안의 승인 업무명만 제시한다.
4. 사용자는 지표를 선택하거나 명확한 기간을 추가한다.
5. 제품은 보완 내용을 포함한 새 질문을 구성한다.
6. 사용자가 확인하면 제품은 새 분석을 시작한다.
7. 이후 과정은 UF-01로 이어진다.

### 대안 흐름

- 사용자는 제안 대신 질문을 직접 수정할 수 있다.
- 보완하지 않고 현재 분석을 종료할 수 있다.

### 실패·차단 흐름

- 승인된 선택지가 없으면 실행하지 않고 지원 범위 부족을 알린다.
- 보완 후에도 의미를 확정할 수 없으면 다시 확인을 요청한다.

### 사용자에게 제공되는 결과

확인이 필요한 이유, 허용된 선택지와 보완된 새 분석 상태를 제공한다.

### 완료 기준

- 사용자 선택 전 데이터 조회가 시작되지 않는다.
- 선택 결과가 새 실행에 반영되고 실제 실행 식별자와 일치한다.

## 7. UF-03. 분석을 저장·재실행하고 이력 확인하기

- **사용자 목적:** 검증된 분석을 반복 업무에 재사용하고 새 실행과 과거 결과를 구분한다.
- **주요 사용자:** 현업 분석 담당자
- **관련 요구사항 ID:** FR-SAV-001~006, NFR-DATA-001~002, NFR-AUD-002
- **시작 조건:** 본인 소유의 성공 또는 허용된 일부 성공 분석이 있다.
- **시작점:** 현재 분석 저장
- **종료 조건:** 새 실행 결과와 보존된 과거 결과를 각각 확인

### 기본 흐름

1. 사용자는 검증된 분석에 이름을 붙여 저장한다.
2. 제품은 저장 가능 상태와 소유권을 확인한다.
3. 제품은 반복 가능한 분석 기준과 원본 근거를 저장한다.
4. 사용자는 이후 저장 분석을 선택해 다시 실행한다.
5. 제품은 현재 권한과 현재 승인 기준을 다시 확인한다.
6. 제품은 과거 실행을 덮어쓰지 않고 새 실행을 만든다.
7. 사용자는 새 결과와 과거 실행의 결과·근거를 각각 확인한다.

### 대안 흐름

- 사용자는 허용된 기간이나 필터를 바꾸어 새 실행을 요청할 수 있다.
- 재실행하지 않고 과거 이력만 확인할 수 있다.

### 실패·차단 흐름

- 실패·취소 또는 검증 결과가 없는 분석은 저장하지 않는다.
- 현재 권한이나 승인 기준과 맞지 않으면 재실행을 차단하고 과거 결과는 보존한다.

### 사용자에게 제공되는 결과

저장 분석, 새 실행과 과거 실행별 상태·기간·결과·근거를 제공한다.

### 완료 기준

- 새 실행과 과거 실행이 다른 식별자로 보존된다.
- 재실행 실패가 과거 결과를 변경하지 않는다.

## 8. UF-04. 분석 결과로 보고서 초안을 만들고 편집하기

- **사용자 목적:** 검증된 분석을 원본 근거가 유지되는 보고서 초안으로 구성한다.
- **주요 사용자:** 현업 분석 담당자
- **관련 요구사항 ID:** FR-RBAC-003, FR-RPT-001~005, FR-RPT-011
- **시작 조건:** 본인 소유의 검증된 분석 결과가 있다.
- **시작점:** 분석 결과를 보고서로 활용
- **종료 조건:** 편집한 초안이 저장되고 같은 구성으로 복원

### 기본 흐름

1. 사용자는 본인의 검증된 분석 결과를 선택한다.
2. 제품은 소유권과 보고서 사용 가능 상태를 확인한다.
3. 사용자는 제목을 지정해 초안 생성을 요청한다.
4. 제품은 원본 설명·표·차트와 연결된 초안을 만든다.
5. 사용자는 텍스트와 블록의 위치·크기를 편집한다.
6. 제품은 원본 분석 근거의 연결을 유지한다.
7. 사용자는 편집 내용을 초안 버전에 저장하고 다시 확인한다.

### 대안 흐름

- 승인본을 변경하려면 기존 승인본을 보존한 채 다음 초안 버전을 만든다.

### 실패·차단 흐름

- 타인 소유, 실패·취소 또는 검증되지 않은 분석에서는 초안을 만들지 않는다.
- 저장에 실패하면 화면만 성공으로 전환하지 않는다.

### 사용자에게 제공되는 결과

원본 분석과 연결된 편집 가능한 보고서 초안과 버전을 제공한다.

### 완료 기준

- 다시 열었을 때 저장한 블록 구성이 복원된다.
- 원본 분석과 결과 근거의 연결이 유지된다.

## 9. UF-05. 보고서를 승인하고 수동 실행하기

- **사용자 목적:** 검토한 보고서 버전을 승인·실행하고 블록별 결과를 확인한다.
- **주요 사용자:** 보고서 관리자
- **관련 요구사항 ID:** FR-RBAC-004~005, FR-RPT-005~010, NFR-DATA-001
- **시작 조건:** 검토할 초안이 있고 보고서 관리자로 로그인했다.
- **시작점:** 보고서 초안 검토
- **종료 조건:** 승인본의 실행 이력과 블록별 상태 확인

### 기본 흐름

1. 관리자는 초안과 원본 분석 근거를 검토한다.
2. 관리자는 검토를 마친 초안 버전을 승인한다.
3. 제품은 승인 버전을 변경할 수 없는 기준본으로 보존한다.
4. 관리자는 승인본을 하나의 기준 시점으로 수동 실행한다.
5. 제품은 각 블록의 원본 분석과 근거를 확인한다.
6. 제품은 블록별 결과를 성공 또는 실패로 기록한다.
7. 제품은 전체 성공·일부 성공·실패를 구분해 실행 이력을 제공한다.

### 대안 흐름

- 일부 성공에서도 성공 블록의 결과와 실패 블록의 원인을 각각 확인한다.
- 승인 후 편집이 필요하면 다음 초안 버전을 만든다.

### 실패·차단 흐름

- 관리자가 아닌 사용자의 승인·실행 요청은 거부해야 한다.
- 미승인 보고서와 원본 근거가 없는 블록은 실행하지 않는다.

### 사용자에게 제공되는 결과

불변 승인본, 보고서 실행 상태, 블록별 결과와 과거 실행 이력을 제공한다.

### 완료 기준

- 승인본이 직접 변경되지 않는다.
- 일부 블록 실패가 전체 성공으로 표시되지 않는다.
- 실제 로그인 역할과 서버 권한이 일치해야 한다.

## 10. UF-06. 보고서 실행 일정을 등록하고 결과 확인하기

- **사용자 목적:** 승인 보고서를 정해진 주기로 중복 없이 실행한다.
- **주요 사용자:** 보고서 관리자
- **관련 요구사항 ID:** FR-RBAC-006, FR-SCH-001~004, FR-RPT-009~010
- **시작 조건:** 관리 가능한 승인 보고서가 있다.
- **시작점:** 반복 실행할 보고서와 주기 지정
- **종료 조건:** 실행 결과와 다음 실행 시각이 기록됨

### 기본 흐름

1. 관리자는 승인 보고서를 선택한다.
2. 일·주·월 중 주기와 최초 실행 시점을 지정한다.
3. 제품은 승인 상태와 관리 권한을 확인한다.
4. 제품은 다음 실행 시각을 가진 일정을 등록한다.
5. 실행 시각이 되면 승인본을 자동 실행한다.
6. 제품은 같은 예약 시각에 하나의 실행만 만든다.
7. 실행 결과를 저장하고 다음 실행 시각을 갱신한다.

### 대안 흐름

- 관리자는 일정을 중지하거나 다시 활성화할 수 있다.
- 일부 실패 결과는 UF-05와 같은 방식으로 확인한다.

### 실패·차단 흐름

- 관리자 권한이 없거나 보고서가 승인 상태가 아니면 일정을 등록하지 않는다.
- 실행 실패를 성공으로 기록하지 않으며 중복 실행을 만들지 않는다.

### 사용자에게 제공되는 결과

일정 상태, 다음 실행 시각과 회차별 보고서 실행 이력을 제공한다.

### 완료 기준

- 동일 예약 시각에 하나의 실행만 존재한다.
- 실행 후 다음 시각이 설정된 주기에 맞게 이동한다.
- 실제 로그인 역할과 예약 관리 권한이 일치해야 한다.

## 11. UF-07. 작성 지원으로 보고서 초안 제안받기

- **사용자 목적:** 검증된 분석 근거로 사람이 검토할 보고서 초안을 제안받는다.
- **주요 사용자:** 보고서 관리자
- **관련 요구사항 ID:** FR-AST-001~002, FR-RPT-002~004, NFR-AUD-003
- **시작 조건:** 사용할 수 있는 검증 분석 자산이 있다.
- **시작점:** 분석 자산과 작성 목적 선택
- **종료 조건:** 편집 가능한 초안 저장 또는 초안 없는 실패 종료

### 기본 흐름

1. 관리자는 검증된 분석과 작성 목적을 선택한다.
2. 제품은 권한과 원본 분석 근거를 확인한다.
3. 제품은 검증된 설명·근거·차트 정보만 작성 범위로 사용한다.
4. 제품은 제목·요약·표·차트 구성을 제안한다.
5. 제품은 제안이 원본 근거와 허용 형식을 지키는지 확인한다.
6. 제품은 제안을 편집 가능한 초안으로 저장한다.
7. 관리자는 내용을 검토·수정하며 별도 승인 전까지 초안으로 유지한다.

### 대안 흐름

- 제안을 사용하지 않고 기존 UF-04 방식으로 직접 편집할 수 있다.

### 실패·차단 흐름

- 모델 또는 결과 검증이 실패하면 초안을 생성하지 않는다.
- 작성 지원은 데이터를 재계산하거나 보고서를 자동 승인하지 않는다.

### 사용자에게 제공되는 결과

원본 근거가 연결된 편집 가능한 제안 초안 또는 명시적 실패 상태를 제공한다.

### 완료 기준

- 제안 수치와 근거가 원본 분석을 벗어나지 않는다.
- 실패 시 새 보고서 정의가 생성되지 않는다.

## 12. UF-08. 외부 도구에서 분석을 읽기 전용으로 조회하기

- **사용자 목적:** 외부 업무 도구에서 본인의 저장 분석 상태와 근거를 안전하게 조회한다.
- **주요 사용자:** 인증된 분석 담당자, 승인된 외부 도구
- **관련 요구사항 ID:** FR-MCP-001~004, NFR-SEC-001~002, NFR-AUD-003
- **시작 조건:** 유효한 인증과 본인 소유 분석 실행이 있다.
- **시작점:** 외부 도구에서 승인 기능 확인
- **종료 조건:** 본인 실행 조회 또는 데이터 변경 없는 거부

### 기본 흐름

1. 사용자는 승인된 외부 도구에서 연결을 시작한다.
2. 외부 도구는 사용자 인증과 도구 식별 정보를 제공한다.
3. 제품은 사용자 역할과 도구의 승인 범위를 확인한다.
4. 제품은 허용된 읽기 전용 기능만 제시한다.
5. 사용자는 본인 분석 실행을 지정한다.
6. 제품은 실행 소유권을 확인한다.
7. 제품은 실행 상태와 저장 근거를 반환하고 호출 근거를 남긴다.

### 대안 흐름

- 사용자는 먼저 허용 기능만 확인하고 실행 조회 없이 종료할 수 있다.

### 실패·차단 흐름

- 인증 실패, 타인 실행, 미등록 또는 쓰기 기능 요청은 결과 없이 거부한다.
- 감사 근거 저장에 실패하면 성공 응답을 반환하지 않는다.

### 사용자에게 제공되는 결과

본인 실행 상태와 근거 또는 요청이 거부된 이유를 제공한다.

### 완료 기준

- 타인 실행과 쓰기 요청에서 제품 데이터가 반환·변경되지 않는다.
- 허용과 거부 모두 감사 근거가 남는다.

## 13. 공통 상태 및 예외 원칙

| 상태 | 사용자에게 보이는 의미 |
|---|---|
| 처리 중 | 분석 또는 보고서 실행이 아직 끝나지 않음 |
| 성공 | 검증된 결과와 근거가 준비됨 |
| 사용자 확인 필요 | 지표나 기간 보완 전에는 실행할 수 없음 |
| 권한 거부 | 현재 역할·소유권으로 이용할 수 없음 |
| 일부 성공 | 일부 데이터 영역 또는 보고서 블록만 성공 |
| 실패 | 결과를 만들거나 저장하지 못함 |
| 근거 부족 | 결과 공개 또는 재사용에 필요한 근거가 부족함 |

오류가 발생하면 현재 상태와 다음 행동을 안내하고, 샘플이나 과거 결과를 새 성공 결과로 보여주지 않는다. 재시도는 새 시도로 기록하며 과거 실행을 덮어쓰지 않는다.
