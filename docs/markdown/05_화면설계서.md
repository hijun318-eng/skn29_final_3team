## 1. 화면설계 개요

### 1.1 서비스 목적

Answervice는 PMS·CRM·POS·시설·연회 시스템에 흩어진 데이터를 자연어로 분석하고, 출처가 확인된 결과를 편집 가능한 보고서로 연결하는 호텔 내부 업무 서비스다.

| 사용자 문제 | 화면이 제공하는 해결 방법 |
|---|---|
| 여러 시스템의 결과를 따로 확인해야 한다. | 질문 한 번으로 승인된 원천의 지표를 비교한다. |
| 데이터 위치와 SQL을 알아야 한다. | 업무 용어로 질문하고 결과·기간·출처를 함께 확인한다. |
| 분석 결과를 보고서로 옮기면 근거가 사라진다. | 분석 결과 ID와 출처를 유지한 채 보고서 블록으로 전달한다. |
| 실패 이유와 다음 행동을 알기 어렵다. | 재질문·권한 부족·부분 완료·원천 장애를 구분해 안내한다. |

### 1.2 대표 사용 흐름

```text
질문 입력
→ 데이터 위치와 권한 확인
→ 안전한 조회 실행
→ 결과·근거 확인
→ 보고서에 담기
→ 블록 편집·검토·실행
```

중간발표 대표 질문은 “7월 마지막 주 객실 매출 감소 구간을 찾고, 예약 채널과 연회 일정 변화를 함께 비교해줘”다. 화면은 PMS 객실 매출·점유율, CRM 직접 예약 비중, Banquet 일정 변경·연계 객실 취소를 하나의 분석으로 보여준다.

### 1.3 화면 공통 원칙

- 결과 가까이에 기간, 단위, 필터, 기준 시각과 데이터 출처를 표시한다.
- 권한이 없거나 안전하지 않은 요청은 실행하지 않고 이유와 다음 행동을 안내한다.
- 일부 원천이 실패하면 성공한 결과와 실패한 범위를 분리한다.
- 보고서에 담을 때 질문·조건·출처·분석 결과 ID를 함께 보존한다.
- 합성 데이터에는 `SYNTHETIC`, seed, schema version을 표시한다.
- 일반 사용자에게 자유 SQL, 원문 DB 오류, credential과 모델 내부 추론을 노출하지 않는다.

## 2. 정보 구조(IA)

### 2.1 사용자 역할

| 사용자 | 주요 목적 | 허용 범위 |
|---|---|---|
| 일반 사용자 | 질문·결과·근거 확인, 보고서 전달 | 분석 챗, 허용된 보고서 조회 |
| 관리자 | 보고서 편집·승인·실행 | 분석 챗, 보고서 전체 |
| 데이터·시스템 관리자 | 데이터 연결·자산·정책 상태 확인 | 카탈로그, 연결, Context, 운영·감사 |
| 감사자 | 권한·실행 증적 확인 | 운영·감사 조회 |

권한 밖 메뉴는 숨기고 직접 URL 접근도 서버에서 다시 거부한다. 화면은 유효 role과 policy version을 표시할 수 있지만 사용자가 자신의 role을 바꾸는 기능은 제공하지 않는다.

### 2.2 메뉴 구조

```text
Answervice
├─ 분석 챗
├─ 보고서
│  ├─ 목록·상세·편집
│  └─ 실행 이력·실행 상세
├─ 데이터 카탈로그
│  ├─ 자산 검색·상세
│  ├─ 연결 상태
│  └─ Context·정책
└─ 운영·감사
   ├─ 요청 검색
   └─ 요청 trace
```

Tool 관리, 문서 RAG, ML-as-a-Tool, 고객 360과 외부 보고서 배포는 현재 범위에서 제외한다. 승인 전에는 메뉴와 직접 route를 모두 차단한다.

## 3. 사용자 흐름

### 3.1 분석에서 보고서까지

1. 사용자가 질문을 입력한다.
2. 시스템이 기간·지표·대상을 확인하고 모호하면 재질문한다.
3. 권한과 데이터 연결 관계를 검사한 뒤 안전한 조회만 실행한다.
4. 사용자는 요약, KPI, 표·차트와 PMS·CRM·Banquet 근거를 확인한다.
5. `보고서에 담기`를 누르면 분석 결과가 보고서 초안에 블록으로 추가된다.
6. 관리자는 블록 위치·크기·문구를 편집하고 보고서를 저장한다.

### 3.2 안전한 중단

| 상황 | 화면 처리 |
|---|---|
| 질문 조건 부족 | 필요한 기간·대상·지표를 다시 묻는다. |
| 권한 부족 | 허용되지 않은 자산과 돌아갈 화면을 안내한다. |
| 안전하지 않은 조회 | 실행하지 않고 안전한 범위의 질문 예시를 제공한다. |
| 일부 원천 장애 | 성공한 수치와 실패한 원천을 분리해 `PARTIAL`로 표시한다. |
| 근거 부족 | 설명과 보고서 삽입을 막고 조건 보완을 요청한다. |

## 5. 화면별 구성 요소와 동작

각 화면은 목적과 핵심 동작만 정의한다. 로딩·빈 값·오류·권한·접근성은 6~7절의 공통 기준을 적용한다.

### 5.1 `SCR-AUTH-001` 로그인·유효 역할

| 구분 | 내용 |
|---|---|
| 목적 | 인증된 사용자와 유효 역할만 서비스에 진입시킨다. |
| 핵심 UI | 서비스 안내, 로그인 폼, 합성 환경 고지 |
| 핵심 동작 | 중복 제출 차단, 성공 시 `/agent`, 실패 시 안전한 사유 표시 |
| 예외 | 세션 만료, 유효 역할 없음, 인증 실패 |
| API 경계 | 인증 방식과 role mapping은 서버 계약 확정 후 연결 |

### 5.2 `SCR-CHAT-001` 분석 챗

| 구분 | 내용 |
|---|---|
| 목적 | 업무 질문을 검증된 분석 결과와 근거로 바꾼다. |
| 핵심 UI | 질문 입력, 처리 단계, 요약·KPI·표·차트, 근거 패널, `보고서에 담기` |
| 핵심 동작 | 질문 전송 후에만 결과 표시, 재질문, 후속 질문, Artifact 전달 |
| 예외 | 0건, 조건 부족, 권한 부족, 안전 차단, 부분 완료, 원천 장애 |
| API 경계 | request 상태·result·evidence·artifact를 서버 값 그대로 표시 |

### 5.3 `SCR-RPT-001` 보고서 목록

| 구분 | 내용 |
|---|---|
| 목적 | 보고서 정의와 최근 실행 상태를 빠르게 찾는다. |
| 핵심 UI | 주기·상태 필터, 보고서 목록, 최근 실행, 새 보고서 |
| 핵심 동작 | 목록→상세·편집·실행 이력 이동, 필터 초기화 |
| 예외 | 보고서 0건, 조회 권한 없음, 최근 실행 없음 |
| API 경계 | definition과 latest run을 구분해 조회 |

### 5.9 `SCR-CONN-001` 연결 상태

| 구분 | 내용 |
|---|---|
| 목적 | PMS·POS·CRM·시설·연회 연결의 현재 상태를 확인한다. |

### 5.10 `SCR-CTX-001` Context·정책

| 구분 | 내용 |

| 목적 | 지표·시간·차원·JOIN·권한 규칙을 읽기 전용으로 확인한다. |
| 핵심 UI | release version, URN↔FQN, metric, time, JOIN, mask policy |
| 핵심 동작 | 버전 전환, 자산 이동, 관계·지표 필터 |
| 예외 | inactive release, 승인되지 않은 JOIN, 정책 불일치 |
| API 경계 | publish·rollback은 승인 workflow 구현 전 비활성 |

### 5.11 `SCR-AUD-001`·`SCR-AUD-002` 운영·감사

| 구분 | 내용 |
|---|---|

## 6. 정상·빈 값·로딩·오류·권한 상태

| 상태 | 사용자에게 보이는 내용 | 가능한 행동 |
|---|---|---|
| `LOADING` | 현재 처리 대상과 진행 단계 | 중복 제출 방지, 가능한 경우 취소 |
| `EMPTY` | 0건인 조건과 기간 | 필터 수정·새 질문 |
| `READY` | 검증된 결과와 근거 | 탐색·편집·보고서 전달 |
| `DELAYED` | 지연 원천과 최근 정상 시각 | 허용된 재시도 |
| `PARTIAL` | 성공·실패 범위와 stale 여부 | 성공 결과 확인·실패 범위 재시도 |
| `ERROR` | 안전한 오류 범주와 `trace_id` | 재시도 또는 관리자 문의 |
| `FORBIDDEN` | 부족한 권한과 허용 화면 | 허용 화면으로 이동 |
| `INSUFFICIENT_EVIDENCE` | 부족한 기간·지표·근거 | 질문 보완; 보고서 삽입 불가 |

보고서는 `DRAFT`, `APPROVED`, `RUNNING`, `SUCCESS`, `PARTIAL_SUCCESS`, `FAILED`를 구분한다. 승인된 definition은 변경하지 않고 새 버전으로 편집한다.

## 7. 접근성 및 반응형 기준

### 7.1 접근성

- 모든 입력에 label과 오류 설명을 연결한다.
- 상태·증감·위험은 색상 외에 문구와 아이콘을 사용한다.
- 차트에는 같은 내용을 확인할 수 있는 표 또는 핵심 수치를 제공한다.
- dialog·drawer는 키보드 focus, Escape, 닫은 뒤 focus 복귀를 지원한다.
- 비동기 진행·저장·오류는 `aria-live`로 전달한다.
- 200% 확대에서도 제목, 입력, 버튼, 표가 겹치지 않아야 한다.

### 7.2 반응형

| 화면 너비 | 기준 |
|---|---|
| 1440px 초과 | sidebar와 주요 보조 패널을 함께 표시 |
| 1025~1440px | 보조 패널 폭 축소, 긴 표는 내부 스크롤 |
| 769~1024px | sidebar·근거 패널을 drawer로 전환 |
| 768px 이하 | 단일 열, 보고서 블록을 `y`, `x` 순서로 배치 |

작은 화면에서도 근거·오류·핵심 행동을 숨기지 않는다. 보고서 블록의 의미와 읽기 순서를 임의로 변경하지 않는다.
