# 프로젝트 개요

- 핵심 메시지: 분산된 호텔 운영 데이터를 질문 한 번으로 조회하되, 권한과 근거를 함께 남긴다.

---

<!-- slide_id: MID-04 -->
# 문제부터 결과까지 하나의 통제 흐름으로 연결한다

- 프로젝트명: Answervice
- 개발 기간: 2026-07-10 ~ 2026-09-03
- 문제: 5개 업무 소스에 분산된 데이터를 수작업으로 조회하고 보고서를 반복 작성한다.
- 해법: DataHub Context와 Trino 읽기 전용 연합 조회로 질문에 필요한 데이터 범위를 확정한다.
- 통제: FastAPI Controller가 G1 Context, G2 SQL, G3 Result Gate를 순서대로 집행한다.
- 결과: 통과한 Evidence와 Artifact만 표·차트·Report 정의로 재사용한다.

---

<!-- slide_id: MID-05 -->
# 자연어 분석과 자동 리포팅이 같은 근거를 사용한다

- 자연어 분석: 질문 → Context → 승인 SQL → 검증 결과
- 근거 표시: 사용한 자산, 지표, 필터, 기간, 기준 시각을 함께 제공한다.
- 자동 리포팅: 통과한 Artifact → Report 정의 → 수동·예약 실행 → 이력·감사
- 안전 경계: frontend와 LLM은 권한, SQL 실행 허용, 결과 정답을 임의로 재판정하지 않는다.

---

<!-- slide_id: MID-06 -->
# 역할이 다른 기술을 하나의 고정 실행 계약으로 묶었다

- Control Plane: FastAPI, OpenAPI, 고정 상태 머신, G1·G2·G3
- AI·ModelOps: Qwen3-4B Base, Node 1·2·2′·3, Prompt Registry, vLLM
- Data Platform: DataHub Core, Trino, 5개 합성 source, 4개 DB engine
- 사용자 경험: React 기반 Chat, Evidence, Chart, Report, Catalog, Audit

# 진행 현황

- 핵심 메시지: I0~I2는 검증 완료, I3는 실제 제품 trace 재검증 단계다.

---

<!-- slide_id: MID-09 -->
# 완료와 대기를 Gate로 구분해 관리한다

- I0 기준 정렬·I1 계약 동결: 완료
- I2 결정론적 전체 왕복: 완료
- I3 General LLM·보안 기준선: 진행
- I4 Reporting·worker·partial: I3 검증 후 시작
- I5 Release: I4 이후 대기
- 현재 이슈: RunPod Pod 시작 실패로 실제 제품 trace 재검증이 차단되어 있으며, 비용 발생 자원은 삭제했다.
- 독립 진행: 중간 발표 자료, 문서 정합성, 로컬 회귀와 다음 Gate 입력 준비는 계속 수행한다.

# 예상 결과 목표

- 핵심 메시지: 빠른 답보다 검증 가능하고 반복 실행 가능한 답을 만든다.

---

<!-- slide_id: MID-11 -->
# 근거가 남는 분석과 반복 실행 가능한 보고서를 완성한다

- 정량 목표: 필수 30건과 Gold 120건 평가, 읽기 전용·보안·장애·복구 검증을 Gate 근거로 남긴다.
- 정성 목표: 사용자가 질문 결과의 데이터 출처와 조건을 이해하고 같은 분석을 Report로 반복 실행한다.
- 현재 모델 결정: Base와 LoRA 비교 결과를 바탕으로 제품 기본값은 Qwen3-4B Base를 유지한다.
- 남은 순서: I3 실제 제품 trace → I4 Report 전체 왕복 → I5 Release·리허설
