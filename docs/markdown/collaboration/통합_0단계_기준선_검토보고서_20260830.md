# 통합 0단계 기준선 검토 보고서

## 1. 목적과 판정

이 문서는 Report UI·Report Assistant·멀티에이전트·RAG·ML을 다음 단계에서 변경하기 전에
`daesung` 기준선의 실제 구현과 실행 경계를 고정한다. 과거 문서나 화면이 아니라
`bc71c33cc55ed2f96fbda1fdd6eb5190d06574df`의 코드·테스트·실행 컨테이너를 기준으로
2026-08-30에 다시 확인했다.

0단계 판정은 **기준선 검토 통과, 목표 서비스 기능은 부분 구현**이다. 현재 소스와 원격
`daesung`은 일치하고 핵심 회귀 Gate는 통과했다. 그러나 정확히 3페이지인 월별 보고서
업데이트, ML·RAG를 포함한 복합 Agent 실행, 자동 capability routing은 아직 완료되지 않았다.

보존한다. `reset`, `clean`, 광범위한 stash 조작은 수행하지 않는다.

## 3. 현재 구현과 미완료 경계

### 3.1 Report Builder와 Report Assistant

확인된 구현은 다음과 같다.

- Report Builder V2, 온디맨드 Assistant·속성 패널, 12열 A4 문서 모델이 운영 코드에 있다.
- 블록 이동은 pointer·touch·keyboard, 그룹 이동, 정렬 가이드, 잘못된 drop의 원본 보존을
  지원한다.
- Report Assistant는 최대 5개 Artifact 결속, `existing_artifact`·`new_data`·`clarification`,
  부분 승인, CAS Revision, 취소·재시도·상태 복구를 지원한다.
- 분석 결과로 초안을 만들 때 제목 제안과 사용자 수정 흐름이 있다.
- Production 경로에서 특정 질문 원문이나 특정 기간만 비교하는 분기와 mock 성공 응답은
  발견하지 못했다.

남은 경계는 다음과 같다.

- `현재 자료 → 월별 → 정확히 3페이지`를 보존하는 typed intent, page budget, overflow 계약이
  없다. 현재 블록 개수와 최종 PDF 물리 페이지 수는 같은 의미가 아니다.
- 편집기 상단 제목은 직접 수정·dirty state·undo·저장과 연결되지 않았고 별도
  `TitleProposal` 계약도 없다.
- Assistant 실행 phase는 복구되지만 UI 대화 메시지는 로컬 상태라 새로고침 후 사라진다.
- 실제 브라우저의 cross-page·touch·keyboard DnD, 방향·zoom 변경, 저장 복구가 아직
  자동 인수 테스트로 고정되지 않았다.
- Review prompt는 일부 블록 제목을 변경할 수 없다고 설명하지만 실제 patch 계약은
  `update_block_title`을 허용해 계약이 일치하지 않는다.
- 월간 호텔 매출 정적 presentation 템플릿은 자동 실행 분기는 아니지만 범용 Composer로
  확장할 때 특정 시나리오 결합을 만들지 않도록 격리해야 한다.

### 3.2 Supervisor와 Agent 경계

- LangGraph는 운영 Conversation 경로에서 실행되지만 현재 그래프는
  `route → 단일 Agent → END` 구조다.
- Supervisor는 일반 GPT router 없이 결정론적으로 동작한다.
- 공개 dispatch의 자동 capability routing은 꺼져 있다.
- 현재 feature flag 상태에서는 Analysis Agent만 registry에 등록된다. RAG를 켜도
  Analysis와 RAG만 등록되며 ML `AgentPort`와 ML capability probe는 없다.
- Agent 간 Artifact 전달, 복합 subtask DAG, typed `@Agent` mention 계약은 아직 없다.
- MCP transport·인증·권한·audit·`tools/list`·`tools/call`은 구현됐지만 공개 도구는
  `analysis.get_run` 한 개다.

따라서 “원인 분석 및 전망” 같은 복합 요청을 현재 성공 처리하면 안 된다. 독립 subtask,
실제 capability receipt, child Artifact를 가진 실행 계획이 추가되기 전까지는 명확화하거나
`BLOCKED`·`PARTIAL`로 종료해야 한다.

### 3.3 RAG와 ML

RAG와 ML runtime 컨테이너는 healthy지만 Backend의 `RAG_FEATURE_ENABLED`와
`ML_FEATURE_ENABLED`는 모두 `0`이다. 비활성 기능은 현재 Backend readiness의 필수 항목이
아니다.

- RAG 후보는 `text-embedding-3-large`의 1024차원 projection과 17개 문서·363개 chunk를
  사용한다. runtime·DB tool gate와 business owner 승인이 닫혀 있어 운영 Agent가 아니다.
- ML serving release는 HGBR v2.2이며 `rooms_sold`, 일 단위, 최대 7일만 지원한다.
  합성 데이터 기반 `CONDITIONAL_PASS`이므로 실제 기업 정확도 증거가 아니다.
- 현재 ML로 “다음 3개월 월별 매출”이나 “9월 한 달 수요”를 처리하는 것은 target·grain·
  horizon 계약 위반이다.
- ML serving 컨테이너의 scikit-learn은 artifact와 같은 `1.9.0`이다. 로컬 테스트 환경의
  `1.8.0` 로딩 경고는 serving mismatch는 아니지만 이후 로컬 검증 환경을 맞춰야 한다.

### 3.4 Node2 sLLM

현재 `ANALYSIS_SQL_GENERATION_MODE=compiler_only`이므로 Node2 adapter·probe·model 호출은
운영 실행과 readiness에서 제외된다. 학습 트랙의 image receipt hash와 example schema는 현재
Node 계약과 불일치하며 CI에서도 비차단 후보 Gate로 실패한다. 이는 후보 승격 금지 증거이며
Report·RAG·ML 계약 작업의 blocker는 아니다.

학습이 완료되기 전에는 receipt를 임의 갱신하거나 후보를 활성화하지 않는다. 새 후보는 동일
typed schema, G2/G3, Trino parity, shadow, canary와 rollback 검증을 거친 뒤에만 교체한다.

## 5. 다음 단계와 커밋 경계

다음 변경은 한 커밋에 섞지 않고 아래 순서로 진행한다.

1. Report 편집기의 제목 직접 편집·제안·저장 계약을 연결한다.
2. DnD와 편집 화면의 접근성·반응형·페이지 간 배치 인수 테스트를 보강한다.
3. `ReportTaskIntent`·`ReportCompositionPlan`·page budget 계약을 추가한다.
4. Report Assistant의 원 요청 보존·대화 복구·부분 승인·Revision E2E를 완성한다.
5. 명시 RAG와 ML Agent 경계를 각각 별도 feature flag로 연결한다.
6. 독립 Artifact를 결속하는 복합 TaskGraph를 구현한 뒤 자동 routing은 마지막에 shadow로
   검증한다.

각 단계는 영향 테스트와 `git diff --check`를 먼저 통과하고, 관련 파일만 staging해 상세한
한국어 커밋을 만든다. push 직전 실제 원격 `daesung` SHA를 다시 확인하고 예상 기준선과 같을
때만 `HEAD:refs/heads/daesung`으로 반영한다.
