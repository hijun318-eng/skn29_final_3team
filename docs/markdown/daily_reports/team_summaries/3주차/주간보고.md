# 3주차 주간보고

## 20260727 ~ 20260728 (3주차)

작성자: 3팀

- 프로젝트 방향·실행계획 정비
  - 멘토링 피드백을 반영해 프로젝트 방향과 기능 범위를 정리하고 DataHub 기반 데이터 분석·자동 리포팅 서비스 기획서와 5인 병렬 구현 작업 매뉴얼을 작성했다.
  - 기술 스택과 실행안을 재검토해 PGroonga·언어별 병렬 스크리닝·`xlm-roberta` encoder, 런타임 모델 4GB 상한·RunPod 학습 전용·APScheduler 영속 JobStore·RSS 자원 기준·CSRF 계약을 반영했다.
- 데이터 허브·메타데이터 조사
  - 데이터 허브의 역할과 메타데이터 관리 방식을 정리하고, LLM이 자연어 질의를 통해 필요한 데이터를 조회·분석하는 과정을 검토했다.
  - DataHub를 실제 DB가 아닌 설명·소유자·용어·품질·계보 메타데이터 관리 도구로 한정하고 최소 적용 범위와 역할별 접근 정책을 제안했다.
- 데이터 허브 시스템 아키텍처 구상
  - FastAPI·Celery·DataHub·Trino·MCP·sLLM의 역할과 연계 방식을 학습했다.
  - DB 연결 관리, 메타데이터 수집, 연합 질의, 고객 360 및 정기 보고서 기능의 처리 흐름을 정리했다.
- Text-to-SQL·배포 아키텍처 설계
  - Text-to-SQL 안전 실행 구조와 기술 아키텍처·배포 토폴로지 시각화 자료를 제작했다.
- 합성 데이터·DB 구조 설계
  - DataHub와 기능 중심 DB 명칭을 기준으로 문서·SQL·파일명과 도메인별 데이터 명세·전체 데이터 목록·ERD 구조를 재설계했다.
  - DB·테이블·컬럼·제약조건 생성용 DDL 작성 기준과 작업지시문을 구체화하고 MVP 데이터 생성 계획과 시스템 구성 범위를 조정했다.
- 프론트 목업·시스템 역할 정교화
  - 목업 기능 우선순위와 신규 화면을 정리하고 DataHub 발행·동기화, Temporal 작업지시, `ai_jobs` 큐 워커의 역할을 구분했다.
- 엔터프라이즈 프론트·화면설계 개편
  - 독립 Vite 기반 목업에 분석 Agent·Customer 360·정기 보고서·데이터 카탈로그·연결 관리 화면과 공통 화면 구조를 구현했다.
  - 정기 보고서 블록 에디터와 데이터 카탈로그·연결 관리 흐름을 연계하고, 화면설계서를 DataHub Core·Trino·Guarded Text-to-SQL·자동 리포팅·운영 감사와 15개 목표 화면 중심의 v5.0으로 개편해 실행과 문서 정책을 검증했다.
- 온톨로지·DB 매핑 검토

- 데이터 확보·합성 범위
