## 1. 목적과 완료 기준

오늘의 목표는 김재홍 로컬에서 DB 6개와 분석 서비스 Trino 1개가 같은 Compose·SQL 기준으로 재현되고, R4 구현이 source DB·API 계약을 침범하지 않는 상태를 만드는 것이다. 이 문서는 다른 팀원의 실행 현황을 기록하지 않는다.

로컬 검증 완료는 다음을 모두 확인했을 때만 판정한다.

1. 빈 synthetic 환경에서 Compose 실행 성공
2. DB 6개와 Trino가 healthy
3. schema·seed·주요 table row count가 동일
4. 컨테이너 재시작 후 데이터 유지
5. 기준 SHA·checksum·이미지·연결 정보가 동결

## 2. 1순위: 김재홍 로컬 재현성 검증표

보존할 데이터가 없는 synthetic 환경에서만 아래를 실행한다.

```powershell
# synthetic 볼륨만 삭제해도 되는지 먼저 확인
docker compose --env-file infrastructure/database/.env -f infrastructure/database/compose.yml down -v
docker compose --env-file infrastructure/database/.env -f infrastructure/database/compose.yml up -d
docker compose --env-file infrastructure/database/.env -f infrastructure/database/compose.yml ps
powershell -NoProfile -ExecutionPolicy Bypass -File infrastructure/database/scripts/start.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File infrastructure/database/scripts/verify.ps1
```

`start.ps1`은 source readonly 계정과 Trino analytics View를 준비한다. Trino의 `serving` catalog는 메모리 기반이므로, Trino 컨테이너 재생성·재시작 뒤에는 반드시 `start.ps1`을 다시 실행한다. `verify.ps1`은 schema·seed 계약, readonly DDL 거부, analytics View 8개 및 주요 row count를 확인한다. POS seed가 완료되기 전에 health만 확인하고 성공으로 기록하면 안 된다.

| 검증자 | Compose 성공 | DB·Trino healthy | 테이블 수 | 주요 row count | Seed | 재시작 후 유지 | 결과 |
|---|---|---|---|---|---|---|---|
| 김재홍 | 통과 | 7개 healthy | 미측정 | 6개 주요 table 통과 | `20260729` | 통과 (`start.ps1` 재적용 포함) | 부분 통과: 빈 볼륨 재생성은 미실행 |

## 3. 2순위: 환경 기준선 동결

기준선은 clean commit에서만 발행한다. `scripts/export-baseline.ps1`은 비밀값을 읽거나 출력하지 않고 SHA와 Compose·SQL checksum을 Markdown으로 만든다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File infrastructure/database/scripts/export-baseline.ps1 `
  -OutputPath docs/markdown/환경_기준선_YYYYMMDD.md `
  -BaselineVersion 2026-07-29.1
```

| 고정 항목 | 값 또는 발행 방법 | 소유자 |
|---|---|---|
| `ENV_BASELINE_VERSION` | `2026-07-29.1`부터 시작, Compose·SQL 변경 시 증가 | R1 |
| `BASE_BRANCH` | `dev` | R1 |
| `BASE_SHA` | clean `dev` commit SHA | R1 |
| Compose·SQL checksum | `export-baseline.ps1` 결과 | R1·R2 |
| schema / seed / scenario | `1.0.0` / `20260729` / `1.0.0` | R2 |
| timezone | `Asia/Seoul` | R1 |
| 이미지·DBMS 버전 | `infrastructure/database/README.md` | R1 |

## 4. 3순위: DB 연결 계약

컨테이너 간 연결에는 `localhost`가 아닌 서비스명과 내부 포트를 쓴다. 외부 포트는 개발 PC에서만 `127.0.0.1`로 사용한다.

| 서비스 | 내부 host:port | 외부 port | 엔진 | DB / schema | 담당 |
|---|---|---|---|---|---|
| app-postgres | `app-postgres:5432` | 15432 | PostgreSQL 16.13 | `app_db` / application schemas | R4 |
| pms-postgres | `pms-postgres:5432` | 15433 | PostgreSQL 16.13 | `pms_db` / `public` | R2 |
| banquet-postgres | `banquet-postgres:5432` | 15434 | PostgreSQL 16.13 | `banquet_db` / `public` | R2 |
| pos-mysql | `pos-mysql:3306` | 13306 | MySQL 8.4.6 | `pos_db` | R2 |
| crm-mssql | `crm-mssql:1433` | 11433 | SQL Server 2022 CU17 | `crm_db` / `dbo` | R2 |
| facility-clickhouse | `facility-clickhouse:8123` | 18123, 19000 | ClickHouse 24.8.4.13 | `facility` / `facility` | R2 |
| trino | `trino:8080` | 18080 | Trino 476 | source 5 catalog + `serving` | R2 |

Readonly 계정 변수는 source별 `*_READONLY_USER`·`*_READONLY_PASSWORD`이고, app runtime은 `APP_DB_USER`, migration은 `APP_MIGRATION_USER`다. 비밀값은 문서·로그·commit에 기록하지 않는다.

## 6. 5·8순위: 공통 API·Fake 실행 계약

`POST /analysis`는 `RECEIVED -> ROUTED -> SUCCEEDED`의 최소 fake 흐름을 반환한다. 실제 G1/G2/G3, SQL 실행, 모델 호출은 아직 연결하지 않는다.

| 항목 | 계약 |
|---|---|
| 요청 Context | `request_id`, `trace_id`, `conversation_id`, `user_id`, `role`, `as_of`, `timezone`, `contract_version` |
| 응답 | `data`, `meta`, `error` |
| `meta` | `request_id`, `trace_id`, `as_of`, `contract_version` |
| 상태 | `RECEIVED`, `ROUTED`, `SUCCEEDED`, `BLOCKED`, `PARTIAL`, `FAILED` |
| 오류 | `CONTEXT_INCOMPLETE`, `ACCESS_DENIED`, `SQL_POLICY_BLOCKED`, `QUERY_SOURCE_FAILED`, `RESULT_EVIDENCE_MISSING`, `PARTIAL_FAILURE`, `INTERNAL_ERROR` |
| OpenAPI | FastAPI 기동 후 `/openapi.json` |

## 7. 7·9순위: 역할별 전달 계약

### R2 요청

R2는 `DataPlatformAdapter`의 실제 구현과 fake 구현을 제공한다. 최소 registry는 `app/backend/contracts/source_registry.v1.json`에 초안으로 제공한다.

```python
search_assets(query, context)
get_asset_schema(urn)
execute_query(sql, parameters, gate_token)
get_query_status(query_id)
cancel_query(query_id)
get_source_health()
```

### R3 전달

| 항목 | 제한 |
|---|---|
| Node request/response | versioned JSON, timeout, invalid JSON 오류를 포함 |
| model/prompt | `model_version`, `prompt_version` 필수 |
| fake model adapter | `ModelAdapter.invoke(payload, timeout_seconds)` |
| 금지 | 권한, SQL 실행 허용, G1/G2/G3 판정 |

### R5 전달

R5는 `/openapi.json`과 공통 상태·오류를 소비한다. fixture는 `success`, `blocked`, `partial`, `failed`를 포함하고 `request_id`·`trace_id`를 표시한다. 프론트엔드는 metric·권한·Gate를 재판정하지 않는다.
