**자기 모순 지점**:

- 이 파일의 docstring(5행)은 "특정 발화나 지표를 하드코딩하지 않는다”고 주장하나 실제 코드는
  한국어 발화 키워드 목록으로 라우트를 분기한다.
- `src/ai/prompt_registry.py:72`의 Node1 프롬프트는 "closed phrase lexicon에 의존·재현 금지"를
  명시하는데, 정작 서버 측 리졸버가 바로 그 폐쇄 어휘 목록으로 동작한다.

**완화 요소**: 키워드는 라우트·기간 파싱·차트 타입 결정에만 쓰이며 metric 선택·SQL 생성·권한 판단에는
관여하지 않는다(해당 영역은 DataHub 거버넌스 대조). 기간 산술 자체는 조합적 수학 규칙이다.

### 1.2 `app/backend/app/services/conversation_orchestrator.py:107-109` — 모델 실패 시 키워드 경로 결합

except Exception as e:

비교해 명확화 요청 또는 typed error로 닫는 방안 검토가 필요하다.

## 2. 정상 확인된 항목 (위상 아님)

### 2.1 자격증명·인증

- app/, src/ 전체에서 `(password|secret|api_key|token)\s*[=:]\s*["']값["']` 패턴 매치 없음.
- `AUTH_SESSION_SECRET`는 기본값 `""`로 fail-closed. `readiness.py:51`에서 최소 32자 검증.
- `infrastructure/database/.env.example`의 모든 값은 `CHANGE_ME_*`/`REQUIRED_EXTERNAL_*` placeholder.
- infrastructure probe 스크립트(verify.ps1, start.ps1)는 env 주입·`--env NAME` 전달 방식이며
  argv/URL에 secret 미노출.
- `test_auth|skip_auth|debug_auth|allow_all` 패턴 app/src 코드에 없음.
- 인증 principal은 저장소 밖 외부 파일에서만 로드(`auth_principal_store.py`).

### 2.2 SQL

- production의 SQL 문자열 리터럴은 전부 App DB 관리 쿼리(alembic 버전 조회, registry 조회, CAS lock,
  멱등키 조회)와 Trino 권한 증명 `SELECT 1`(`trino_async.py:266`)뿐.
- 분석용 Trino 쿼리는 runtime Context(asset·field·metric·join·time·permission 계약) 기반 생성 경로만 존재.
- prompt·migration·helper가 특정 질문의 완성 CTE를 반환하는 지점 없음.
- `routing_service.py`는 "질문 문구나 keyword mapping 없이 dynamic route"를 명시하고
  template SQL은 DB 승인 행에서만 원자적으로 조회.

### 2.3 실패 처리 (fallback)

검증한 `except Exception` 지점 15곳 전부 typed 실패로 마감:

| 위치 | 처리 |
|---|---|
| `readiness.py:104-109` | not_ready 반환 (fail-closed) |
| `router.py:309/325/408` | typed failure + `fail_run` + raise |
| `report_execution.py:192/234/337` | typed BlockFailure로 기록 |
| `report_scheduler.py:117-119` | not_ready + 로그 |
| `database.py:91-95` | rollback 후 re-raise |
| `catalog_snapshot.py:81-85` | inflight 정리 후 re-raise (stale 성공 대체 금지) |
| `conversation_repository.py:106-109` | 멱등 충돌 변환만, 나머지 re-raise |
| `report_router_support.py:356` | typed 500 HTTPException |
| `report_document.py:145-146` | `ReportDocumentRenderError` 래핑 후 전파 |

추가 감시 장치:

- `model_adapter.py:216-217` — model fallback 감지 시 `raise TimeoutError("production model fallback is not a product result")`로 거부.
- `async_model_client.py:155` — trace 메타데이터의 `"fallback": False` 고정값.

### 2.4 데이터 원본 경로

- `context_builder.py` — metric/dimension 정의를 DataHub glossary에서 읽은 값으로만 구성.
- `catalog_snapshot.py` — live DataHub readback + TTL 5초 캐시. 고정 snapshot 아님.
- `prompt_registry.py` — "완성 SQL 예시 반환 금지"를 prompt 지침에 명시.
- DataHub semantic authoring — policy는 stdin 공급 후 DataHub 발행 → live readback.
  로컬 JSON persist 없음(SEMANTIC_AUTHORING.md "runtime never reads a release-specific JSON file").
- `report_document_values.py:27`의 `SYNTHETIC_WARNING`("합성 데모 데이터 · 실제 호텔 운영 성과가 아님")은
  `_report_is_synthetic(source)` 조건부 표시로 합성 release 계약의 경고 문구. demo 데이터 로드 경로가 아님.

### 2.5 기타 참고

- `app/backend/app/contract_examples.py`, `trace_examples.py` — app 패키지 내 존재하고
  `api/router.py:14`이 import하나, 용도는 OpenAPI 문서 메타데이터(`responses`/`openapi_examples`) 전용.
  docstring에 "endpoint 실행, 분석 결과 생성, fallback에 참여하지 않는다" 명시.
  허용 범주(문서화 목적)이나 app 패키지 밖 문서 도구 경로로의 이동 검토 가치 있음.
- frontend의 "fallback" 매치는 모두 UI 렌더링 폴백(차트 실패 시 안내, Suspense 로딩, 에디터 기본 텍스트).
- `reportTableRows.js`의 `sampleReportTableRows`는 표 필수요소 균등 sampling 로직(더미 아님).
- migration `20260812_12`의 `INSERT INTO tooling.tool_registry` — MCP 도구 등록 row 1건(도구 메타데이터).
