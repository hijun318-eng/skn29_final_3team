## 핵심 연결 관계

```text
hotel_entities ─ hotel_code ─ PMS / POS / Banquet / Facility / Trino
calendar_daily ─ business_date ─ 재고·매출·인력·자원·VOC
event_master ─ event_id ─ hotel_event_effect 및 도메인 이벤트 분석
pms_stays ─ stay_id ─ POS linked_stay_id / folio / CRM VOC
pos_orders ─ order_id ─ items·payments / folio source_transaction_id / points
banquet_bookings ─ banquet_event_id ─ revenue lines / room blocks / PMS 예약
crm_voc_reviews ─ voc_review_id ─ crm_voc_analysis
facility_master ─ facility_id ─ usage / incidents / resources
```

다중 DB 간 연결은 물리 FK가 아니라 Trino 검증 SQL의 논리 FK다. 객실유형은 `hotel_code + room_type_code` 복합키로 확인한다.

## 2026년 9월 시연용 확장 설계

- 한국천문연구원 2026 월력요항, 2026-06-03 지방선거일과 법 개정 이후 행정안전부가 확인한 2026-07-17 제헌절 공휴일을 달력에 반영했다.
- 워커힐 공식 페이지의 Spring Forest·Jazz Picnic(2026-04-22~06-07), Summer Pairing·Just Summer(2026-05-11~08-31), Riverpark(2026-06-26~08-30)를 이벤트 앵커로 사용한다.
- 2026 메뉴 가격 이력을 추가하고 PMS folio·POS ROOM_CHARGE·CRM 포인트의 가격 산식을 함께 맞췄다.
- 다박 교차도메인 여정은 972개이며 POS ROOM_CHARGE 주문은 2,916개다.
- 연회 객실블록은 2,919개이며 PMS bridge 예약과 같은 ID·날짜 계약을 사용한다.
- 이벤트별 호텔 효과는 동일하지 않으며 Grand·Vista·Douglas별 가중치와 포화 상한이 다르다.

공식 자료는 존재와 기간의 근거다. 객실 수·OCC·ADR·매출·참석자·효과 크기는 합성 가정이며 실제 워커힐 실적으로 해석하면 안 된다.

`evidence_cutoff_at`은 2026-08-15 12:00 KST이고 `scenario_as_of_date`는 2026-08-31이다. 2026-08-16~08-31 행은 9월 시연을 위해 공식 행사·판매 기간과 명시적 합성 규칙으로 만든 시나리오 데이터다. `is_forecast=false`는 이 동결 시나리오에 포함됐다는 뜻이며 패키지 생성일 현재 실제 관측 실적이라는 뜻이 아니다.

## 실행 순서

1. 폴더별 `00` 사전점검
2. 각 엔진에서 파일 번호 순서대로 실행
3. 5개 원천 DB의 `50_*_validation.sql` 확인
4. 원천 검증 통과 후 `06_trino_serving`
5. 마지막으로 V4.3 현실성 검증 SQL 6개 실행

통합 SQL로 합치지 않는다. 모든 DDL에는 DB 네이티브 방식의 테이블·컬럼 설명이 포함되어 있다.
